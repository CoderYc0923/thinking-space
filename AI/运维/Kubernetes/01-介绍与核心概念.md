# 01 · Kubernetes 介绍与核心概念

> 一句话：K8s 是 **容器编排平台**——在一堆机器上，按你声明的期望，自动部署、扩缩、自愈、暴露服务。

---

## 一、为什么需要 K8s

Docker 解决了「打包一致、单机跑起来」。上多台机器、多个副本后会出现：

- 容器挂了谁拉起来？  
- 流量怎么打到多个副本？  
- 发版怎么滚动替换？  
- 配置、密钥怎么注入？  

K8s 就是来管这些事的。你可以先不用它（单机 Docker Compose 足够）；服务多了、要弹性与标准化交付时再上。

---

## 二、心智模型（最重要）

```text
Cluster（集群）
 └── Node（节点）= 一台机器（云主机 / 虚拟机 / 物理机）
      └── Pod（最小调度单位）
           └── Container（真正跑你应用的容器）
```

| 概念 | 是什么 | 常见误解 |
|------|--------|----------|
| **Node** | 一台服务器，上面有 kubelet | ❌ 不是「一个 Docker 容器叫节点」 |
| **Pod** | 1～多个容器的组合，共享网络命名空间 | ❌ 不是镜像；是运行中的一组容器 |
| **Container** | 镜像跑起来的实例 | 可以是 containerd 拉起的，不必须叫 Docker |
| **Cluster** | 多个 Node + 控制面 | 学习可用单节点集群 |

**kind** 等工具会用容器「假装」成多个 Node，那只是学习技巧，生产里 Node 仍是机器。

---

## 三、控制面 vs 工作节点（简化）

```text
控制面（Control Plane）
  - API Server：所有操作的入口（kubectl 跟它说话）
  - Scheduler：Pod 放到哪台 Node
  - Controller Manager：维持「期望状态」（副本不够就再起）
  - etcd：存集群状态

工作节点（Worker Node）
  - kubelet：管本机 Pod
  - 容器运行时：containerd 等
  - kube-proxy：协助 Service 网络
```

单节点发行版（如 k3s）会把这些塞在一台机器上，方便学习。

## 四、常用资源对象（先认名字）

K8s 用 **声明式 API**：你写「我想要什么」，控制器负责逼近。

| 对象 | 作用 |
|------|------|
| **Deployment** | 管无状态应用的副本、滚动更新（最常用） |
| **Pod** | 最小运行单元；一般不直接长期手管 Pod，而用 Deployment |
| **Service** | 给一组 Pod 一个稳定访问入口（ClusterIP / NodePort / LoadBalancer） |
| **Ingress** | HTTP/HTTPS 路由（域名、路径 → Service），常配 Nginx Ingress |
| **ConfigMap** | 非敏感配置 |
| **Secret** | 敏感配置（密码、证书；注意仍要管权限） |
| **Namespace** | 逻辑隔离（dev/prod、不同团队） |
| **Volume / PVC** | 持久存储声明（数据库等有状态要额外设计） |

关系直觉：

```text
Deployment ──创建/维持──▶ 多个 Pod
Service    ──选中标签──▶ 这些 Pod，提供固定 DNS/端口
Ingress    ──域名路径──▶ Service
```

## 五、和 Docker Compose 对照

| 你熟悉的 | K8s 大致对应 |
|----------|----------------|
| `docker run` / compose `services` | Deployment + Pod 模板 |
| compose `ports` | Service / Ingress |
| compose `environment` / `env_file` | ConfigMap / Secret / env |
| compose `volumes` | Volume / PVC |
| `docker compose up -d` 扩副本 | `kubectl scale` / Deployment replicas |
| 容器挂了手动重启 | 控制器自动拉起（重启策略） |

Compose：单机编排。K8s：集群编排 + 更强的自愈与生态。

## 六、基本工作流（全栈视角）

```text
1. 用 Dockerfile 打镜像，推到镜像仓库
2. 写 Deployment YAML（镜像、副本、端口、探针）
3. 写 Service（集群内访问）
4. 需要外网域名 → Ingress
5. kubectl apply -f ...
6. kubectl get/describe/logs 观察与排障
```

应用代码几乎不变；变的是「怎么声明运行方式」。

---

## 七、什么时候该上 / 不该上

| 更适合 K8s | 可以先不上 |
|------------|------------|
| 多服务、要滚动发布与扩缩 | 个人站、单机轻量应用 |
| 多环境标准化交付 | 一台轻量 + Docker Compose 已够 |
| 团队已有镜像与 CI | 还不会容器就先学 Docker |

你当前阿里云轻量 + Compose/宝塔：先学概念和本地/单机 k3s；业务真要上再迁 ACK。

## 八、名词速查

| 词 | 含义 |
|----|------|
| 编排（Orchestration） | 自动调度、部署、扩缩、恢复 |
| 期望状态（Desired State） | YAML 里写的「要 3 个副本」等 |
| 标签（Label） | 键值对，用来筛选 Pod（Service 靠它选后端） |
| 探针（Probe） | 存活/就绪检查，决定重启或是否接流量 |
| CNI | 容器网络插件 |
| OCI | 镜像/运行时开放标准；Docker 镜像一般兼容 |
