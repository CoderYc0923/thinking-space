# 02 · 基础用法与常用命令

> 前提：已有可用集群（kubectl 能连上）。  
> 本机验证：`kubectl cluster-info` / `kubectl get nodes`

---

## 一、kubectl 是什么

`kubectl` = 和 API Server 说话的命令行客户端。  
多数操作等价于：提交或查询一段 YAML 声明的资源。

```bash
# 看当前上下文（连的哪个集群）
kubectl config get-contexts
kubectl config current-context
```

## 二、日常查看（先练熟）

```bash
# 节点
kubectl get nodes

# 默认命名空间的 Pod
kubectl get pods
kubectl get pods -A              # 所有命名空间
kubectl get pods -o wide         # 带 IP、所在节点

# 常用资源一览
kubectl get deploy,svc,ingress,cm,secret

# 详情（排障第一武器）
kubectl describe pod <pod名>
kubectl describe deploy <部署名>

# 日志（类似 docker logs）
kubectl logs <pod名>
kubectl logs -f <pod名>                  # 跟踪
kubectl logs <pod名> -c <容器名>         # 多容器 Pod
kubectl logs <pod名> --previous          # 上一次崩溃的容器日志
```

## 三、最小 Deployment + Service 示例

保存为 `hello.yaml`：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello
spec:
  replicas: 2
  selector:
    matchLabels:
      app: hello
  template:
    metadata:
      labels:
        app: hello
    spec:
      containers:
        - name: web
          image: nginx:1.25-alpine
          ports:
            - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: hello
spec:
  selector:
    app: hello
  ports:
    - port: 80
      targetPort: 80
  type: ClusterIP          # 集群内访问；练外网可改 NodePort
```

```bash
kubectl apply -f hello.yaml
kubectl get deploy,pod,svc
kubectl rollout status deploy/hello
```

访问（ClusterIP 仅集群内）：

```bash
# 临时起一个带 shell 的 Pod 去 curl
kubectl run tmp --rm -it --image=curlimages/curl -- restart=Never -- curl -s http://hello
```

改成 NodePort 时：

```yaml
  type: NodePort
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080    # 30000-32767
```

然后浏览器访问 `http://<节点公网IP>:30080`（安全组要放行）。

## 四、变更、扩缩、回滚

```bash
# 扩缩
kubectl scale deploy/hello --replicas=3

# 改镜像（发版）
kubectl set image deploy/hello web=nginx:1.26-alpine
kubectl rollout status deploy/hello
kubectl rollout history deploy/hello
kubectl rollout undo deploy/hello          # 回滚上一版

# 删
kubectl delete -f hello.yaml
# 或
kubectl delete deploy hello
kubectl delete svc hello
```

## 六、配置与密钥（入门）

```bash
# 从文件创建 ConfigMap / Secret
kubectl create configmap app-config --from-literal=ENV=prod
kubectl create secret generic app-secret --from-literal=password=xxx

kubectl get cm,secret
kubectl describe cm app-config
```

在 Deployment 里用 `envFrom` / `valueFrom` 注入（细节以后专项写）。  
注意：Secret 默认只是 base64，不是加密保险箱，还要靠 RBAC 与权限。

## 七、命名空间

```bash
kubectl get ns
kubectl create ns demo
kubectl -n demo apply -f hello.yaml
kubectl -n demo get pods
```

养成习惯：生产相关操作带 `-n`，避免打到 `default` 搞混。

## 八、排障最小路径

```text
1. kubectl get pods          → Running？Pending？CrashLoopBackOff？
2. kubectl describe pod ...  → Events 里看拉镜像失败、调度失败、探针失败
3. kubectl logs ...          → 应用报错原文
4. kubectl get svc,endpoints → Service 有没有选中后端 Pod
5. 节点：kubectl get nodes / 机器磁盘内存（和线上排查同一套）
```

| Pod 状态 | 常见原因 |
|----------|----------|
| **Pending** | 资源不够、调度不了、PVC 挂不上 |
| **ImagePullBackOff** | 镜像名/仓库权限/网络 |
| **CrashLoopBackOff** | 进程启动即挂，看 logs |
| **Running 但不通** | Service 标签不匹配、端口错、探针未就绪 |

和 Docker 对照：`docker ps` → `kubectl get pods`；`docker logs` → `kubectl logs`；`docker exec` → `kubectl exec`。

## 九、单机快速起集群（任选）

### k3s（Linux 服务器常见）

```bash
curl -sfL https://get.k3s.io | sh -
sudo kubectl get nodes
# kubeconfig 一般在 /etc/rancher/k3s/k3s.yaml
```

### kind（本机已有 Docker）

```bash
kind create cluster --name dev
kubectl get nodes
```

内存紧张时优先 k3s/kind，别在小机器上硬上完整 kubeadm 多组件。

## 十一、命令速查表

| 目的 | 命令 |
|------|------|
| 看 Pod | `kubectl get pods -o wide` |
| 详情 | `kubectl describe pod <名>` |
| 日志 | `kubectl logs -f <名>` |
| 进容器 | `kubectl exec -it <名> -- sh` |
| 应用清单 | `kubectl apply -f x.yaml` |
| 删除清单 | `kubectl delete -f x.yaml` |
| 扩缩 | `kubectl scale deploy/<名> --replicas=N` |
| 发版 | `kubectl set image deploy/<名> <容器>=<镜像>` |
| 回滚 | `kubectl rollout undo deploy/<名>` |
