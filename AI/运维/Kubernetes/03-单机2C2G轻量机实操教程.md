# 03 · 单机 2 核 2G 轻量应用服务器实操教程

> 目标：在 **一台 2C2G 阿里云轻量机** 上，用 **k3s** 学会：常用命令 → 部署应用 → 基础排障。  
> 前置：会 SSH、会一点 Docker 概念；已读 [01](./01-介绍与核心概念.md) 更佳。  
> 耗时：约 1～2 个晚上（可拆开做）。

---

## 0. 为什么选 k3s（而不是完整 kubeadm / kind）

| 方案 | 2G 内存 | 说明 |
|------|---------|------|
| **k3s** | ✅ 较合适 | 专为轻量设计，单机即可 |
| kubeadm 完整版 | ❌ 偏紧 | 组件多，2G 很容易卡死 |
| kind（Docker 里再套节点） | ⚠️ 更吃内存 | 机器上若已有宝塔/MySQL/Docker，更容易爆 |

本教程全程按 **k3s 单节点** 来。

---

## 1. 开始前：资源与风险（必读）

2G 机器很「刚好」，请先评估：

```bash
free -h
df -h
```

| 情况 | 建议 |
|------|------|
| 已跑宝塔 + MySQL + 多个站点 | **强烈建议**：另开一台「纯练机」，或先停掉非必要服务再装 k3s |
| 空闲内存经常 < 300MB | 先加 **1G swap**，再装（见下） |
| 磁盘 < 5G 可用 | 先清日志/镜像，再装 |

### 1.1 加 swap（2G 机强烈建议）

```bash
# 若还没有 swap
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

### 1.2 安全组 / 防火墙

练 NodePort 时，轻量控制台放行例如：**30080**（或你选的 NodePort）。  
k3s 安装与拉镜像需要出网。

### 1.3 本教程约定

- 系统：Ubuntu 22.04 / CentOS 系均可（命令以通用为主）  
- 用户：可用 `root` 或 `sudo`  
- 应用示例：超小镜像 `nginx:1.25-alpine`（省内存）

## 2. 安装 k3s

### 2.1 一键安装（国内网络慢可加镜像，见文末附录）

```bash
curl -sfL https://get.k3s.io | sh -
```

为省资源，可用精简安装（关掉部分组件，入门够用）：

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--disable=traefik --disable=metrics-server" sh -
```

> - 关掉 Traefik：省一点内存；外网先用 **NodePort**，不必先学 Ingress。  
> - 以后要练 Ingress，可再装 ingress-nginx，或重装时去掉 `--disable=traefik`。

### 2.2 确认装好

```bash
sudo systemctl status k3s --no-pager
sudo k3s kubectl get nodes
sudo k3s kubectl get pods -A
```

期望：

- `k3s` 服务 `active (running)`  
- `get nodes` 里有一台 `Ready`  
- 系统 Pod 多数 `Running`（2G 上可能要等 1～2 分钟）

### 2.3 让 kubectl 好用（可选）

```bash
# 当前用户可直接用 kubectl
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown "$USER":"$USER" ~/.kube/config
export KUBECONFIG=~/.kube/config

# 验证
kubectl get nodes
```

下面统一写 `kubectl`；若未拷配置，所有命令前加 `sudo k3s kubectl`。

### 2.4 若安装失败 / 机器卡死

```bash
sudo journalctl -u k3s -n 80 --no-pager
free -h
# 卸载重来（见附录）
```

内存被宝塔吃光时：先停站点/面板相关服务，或换干净轻量机。

## 3. 学命令：每天必会的一组

先只看，不部署：

```bash
kubectl get nodes -o wide
kubectl get ns
kubectl get pods -A
kubectl cluster-info
```

记这三个动词：

| 动词 | 用途 |
|------|------|
| `get` | 列表 |
| `describe` | 详情 + Events（排障核心） |
| `logs` | 容器日志 |

```bash
# 练习：随便看一个系统 Pod
kubectl -n kube-system get pods
kubectl -n kube-system describe pod <任意一个 Running 的 pod 名> | head -60
```

## 4. 部署第一个应用

### 4.1 写清单

```bash
mkdir -p ~/k8s-lab && cd ~/k8s-lab
cat > nginx-demo.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-demo
  labels:
    app: nginx-demo
spec:
  replicas: 1          # 2G 机器先 1 副本；学会后再 scale 到 2
  selector:
    matchLabels:
      app: nginx-demo
  template:
    metadata:
      labels:
        app: nginx-demo
    spec:
      containers:
        - name: nginx
          image: nginx:1.25-alpine
          ports:
            - containerPort: 80
          resources:
            requests:
              cpu: "50m"
              memory: "64Mi"
            limits:
              cpu: "200m"
              memory: "128Mi"
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-demo
spec:
  selector:
    app: nginx-demo
  type: NodePort
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080
EOF
```

### 4.2 应用并观察

```bash
kubectl apply -f nginx-demo.yaml
kubectl get deploy,pod,svc -o wide
kubectl rollout status deploy/nginx-demo
```

期望：`Pod` 为 `Running`，`Service` 类型 `NodePort`，端口 `30080`。

### 4.3 访问

```bash
# 本机测
curl -I http://127.0.0.1:30080

# 浏览器（需安全组放行 30080）
# http://<轻量公网IP>:30080
```

### 4.4 日志与进容器

```bash
POD=$(kubectl get pod -l app=nginx-demo -o jsonpath='{.items[0].metadata.name}')
echo "$POD"
kubectl logs "$POD"
kubectl exec -it "$POD" -- sh -c "hostname; ls /usr/share/nginx/html"
```

## 5. 练发布：扩缩、换镜像、回滚

> 2G 上 `replicas=2` 一般还能扛；不要一次拉到 5。

```bash
# 扩到 2
kubectl scale deploy/nginx-demo --replicas=2
kubectl get pods -o wide

# 发版（换镜像）
kubectl set image deploy/nginx-demo nginx=nginx:1.26-alpine
kubectl rollout status deploy/nginx-demo
kubectl rollout history deploy/nginx-demo

# 回滚
kubectl rollout undo deploy/nginx-demo
kubectl get pods
```

对照理解：

- `scale` → 副本数  
- `set image` → 滚动更新  
- `rollout undo` → 回上一版

## 6. 排障实战（故意搞坏再修）

每做一题，强制走完：**get → describe → logs**。

### 练习 A：错误镜像名（ImagePullBackOff）

```bash
kubectl set image deploy/nginx-demo nginx=nginx:this-tag-does-not-exist
kubectl get pods
kubectl describe pod -l app=nginx-demo | tail -30
```

你应看到：`ImagePullBackOff` / `ErrImagePull`，Events 里拉镜像失败。

恢复：

```bash
kubectl set image deploy/nginx-demo nginx=nginx:1.25-alpine
kubectl rollout status deploy/nginx-demo
```

### 练习 B：进程启动失败（CrashLoopBackOff）

```bash
kubectl set image deploy/nginx-demo nginx=busybox:1.36
# busybox 默认没有一直前台跑的 nginx，容易反复退出
kubectl patch deploy nginx-demo --type='json' -p='[
  {"op":"replace","path":"/spec/template/spec/containers/0/command","value":["sh","-c","exit 1"]}
]'
kubectl get pods
sleep 5
kubectl logs -l app=nginx-demo --tail=20
kubectl describe pod -l app=nginx-demo | tail -40
```

理解：`CrashLoopBackOff` = 容器反复崩溃，**先看 logs**。

恢复到正常 nginx（简单做法：重 apply）：

```bash
kubectl delete deploy nginx-demo svc nginx-demo
kubectl apply -f nginx-demo.yaml
```

### 练习 C：Service 选不中 Pod（标签错误）

```bash
# 把 Service 的 selector 改错
kubectl patch svc nginx-demo --type='json' -p='[
  {"op":"replace","path":"/spec/selector/app","value":"wrong-name"}
]'
kubectl get endpoints nginx-demo
curl -I http://127.0.0.1:30080 || true
```

`endpoints` 为空 → Service 没有后端。  
恢复：

```bash
kubectl patch svc nginx-demo --type='json' -p='[
  {"op":"replace","path":"/spec/selector/app","value":"nginx-demo"}
]'
kubectl get endpoints nginx-demo
curl -I http://127.0.0.1:30080
```

### 排障口诀（贴在备忘录）

```text
Pending           → describe：资源/调度/磁盘
ImagePullBackOff  → describe Events：镜像名/网络/权限
CrashLoopBackOff  → logs：应用为什么退出
Running 但访问失败 → get endpoints / 看 Service 标签与端口 / 安全组
机器整体很卡      → free -h；别盲目加副本
```

## 7. 再部署一个「自己的」小应用（可选）

若你有自己的镜像仓库，把 Deployment 的 `image` 换成你的后端镜像即可。  
2G 上注意：

- `replicas: 1`  
- 写上 `resources.requests/limits`  
- 数据库 **不要** 硬塞进同一台练 K8s（宝塔 MySQL 已占内存）；练应用部署即可  

无自有镜像时，用官方小镜像继续练命令即可。

## 附录 A：安装慢 / 拉不了镜像

- 轻量机出网：能 `curl -I https://github.com` 或换安装源（搜「k3s 国内安装」当前可用镜像站，地址常变，以你环境为准）  
- 应用镜像拉不动：可配置容器运行时镜像加速（k3s 用 containerd；需改 `/etc/rancher/k3s/registries.yaml` 后重启 k3s）。不会改就先用已能拉取的小镜像练命令。

## 附录 B：和「完整 K8s」差异（心里有数即可）

k3s 仍是 Kubernetes API，`kubectl` 用法通用；组件做了裁剪。以后上 ACK，命令习惯可迁移。
