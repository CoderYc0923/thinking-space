> 红黑树是**自平衡二叉查找树**，用于解决普通 BST 在有序数据下退化成链表，查询退化到 O (n) 的问题。
>
> 时间复杂度：查找 / 插入 / 删除均为 \(O(logn)\)。
>
> Java `TreeMap`、C++ `std::map`底层就是红黑树。



### 五条核心性质（必须全部满足）：

- 每个节点，颜色只能是**红色**或者**黑色**
- 根节点一定是黑色
- 所有叶子 (NIL 空节点) 都是黑色
- **红色节点的两个子节点必须是黑色**（不能出现两个红节点相连，红父红子非法）
- 从任意节点出发，到它所有后代叶子节点，**路径上黑色节点数量相等**（黑高一致）

> 重点：性质 4 约束不能连续红；性质 5 保证最长路径不会超过最短路径的 2 倍，树不会严重失衡



### 核心操作：旋转

旋转不会破坏二叉搜索树大小关系，只调整结构，分为左旋、右旋

- **左旋 (左旋转)**：以某节点为轴，右孩子上来顶替自己，右孩子的左子树过继给自己当右孩子
- **右旋 (右旋转)**：以某节点为轴，左孩子上来顶替自己，左孩子的右子树过继给自己当左孩子

伪代码示意：

```js
// 左旋 x
leftRotate(x):
    y = x.right
    x.right = y.left
    if y.left != NIL:
        y.left.parent = x
    y.parent = x.parent
    // x父节点指向y
    if x.parent == NIL: root = y
    else if x == x.parent.left: x.parent.left = y
    else: x.parent.right = y
    y.left = x
    x.parent = y
```



### 插入逻辑

新插入节点默认**红色**。

> 为什么不默认黑色？插入黑色会直接破坏性质 5，导致黑高不一致，修复代价很大；插入红色最多只违反性质 4（红连红），修复简单。

插入后分几种 case 修复冲突（父节点为红才需要修复，父黑直接结束）：

- **叔叔节点是红色**：父、叔变黑，祖父变红，把冲突向上传递，继续处理祖父
- **叔叔黑色，当前节点是右孩子 (左斜)**：先左旋父节点，转成 case3
- **叔叔黑色，当前节点是左孩子 (直线)**：祖父右旋；父节点变黑，原祖父变红

> 插入最多 2 次旋转即可完成修复



### 删除逻辑（红黑树最难）

删除比插入复杂，删除后会产生**“双重黑色”**问题：某个节点额外背负一层黑色，用来维持黑高，需要通过旋转 + 变色消除双重黑。

删除场景分类：

- 删除红色节点：直接删，不破坏任何性质，结束
- 删除黑色节点：会丢失一个黑色，产生双重黑，需要循环向上修复

修复双重黑的 4 种经典 case：

- 兄弟节点为红：旋转，把兄弟变黑，父变红，转换为兄弟黑的场景
- 兄弟是黑，兄弟两个孩子也都是黑：把兄弟变红，双重黑向上抛给父节点
- 兄弟黑，兄弟左红右黑：右旋兄弟，变色，转为 case4
- 兄弟黑，兄弟右孩子红：父节点旋转，颜色交换，清除双重黑，处理完成

> 删除最多 3 次旋转





### 和 AVL 树对比（面试高频）

| 特性         | 红黑树                               | AVL 树                                  |
| ------------ | ------------------------------------ | --------------------------------------- |
| 平衡依据     | 红黑 5 条规则，最长路径≤2 倍最短路径 | 左右子树高度差绝对值≤1                  |
| 平衡严格度   | 弱平衡                               | 强平衡                                  |
| 旋转次数     | 插入最多 2 次，删除最多 3 次         | 插入最多 2 次，删除最坏 O (logn) 次旋转 |
| 查询性能     | 略差                                 | 更好，高度更均衡                        |
| 插入删除性能 | 旋转少，写操作更快                   | 旋转多，写开销大                        |
| 应用场景     | TreeMap、std::map，高频写场景        | 数据库索引等读多写少场景                |
