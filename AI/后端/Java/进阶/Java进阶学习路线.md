# Java 进阶学习路线

> **定位**：在已有「Java 基础 + Spring Boot 单体 + MySQL + Redis」基础上，向中高级后端推进  
> **原则**：项目落地优先，面试题为辅；少回头刷语法，多串中间件链路  
> **技术基线**：JDK 17/21 + Spring Boot 3 + Spring Cloud Alibaba

---

## 一、当前基础盘（默认已具备）

以下内容按「笔记已覆盖、能讲清原理、能写小 Demo」视为达标，不再作为主线重复学：

| 模块 | 覆盖要点 |
|------|----------|
| Java 语言 | OOP、集合、泛型、异常、反射、注解、序列化、Stream、CompletableFuture |
| 并发 | 线程、JMM、synchronized / Lock、AQS、ThreadLocal、线程池基础 |
| IO / 网络 | BIO / NIO / AIO 概念，Netty / RPC 有初步笔记 |
| Spring Boot | 启动流程、MVC、AOP、拦截器/过滤器、统一异常、RBAC、分层模型 |
| MySQL | 索引、事务、MVCC、锁、redo/undo/binlog、Explain 与 SQL 优化 |
| Redis | 基础结构、缓存场景、分布式锁 |
| 工程周边 | Docker、Nginx、分库分表概念、MQ 异步通信概念 |

**真正缺口**：微服务闭环、MQ 可靠性深度、分布式一致性、JVM 线上排查、可观测与 K8s。

## 三、阶段 1：微服务最小闭环（优先，4～6 周）

> **目标**：能把单体拆成 2～3 个服务，说清「请求怎么进来、怎么找服务、挂了怎么办」。

### 3.1 必学组件（Spring Cloud Alibaba）

| 组件 | 学什么 | 通关标准 |
|------|--------|----------|
| **Nacos** | 服务注册发现、配置中心、命名空间/分组 | 服务上下线后调用方能感知；配置热更新生效 |
| **OpenFeign** | 声明式调用、超时、重试、负载均衡 | 跨服务调用可降级、超时可配置 |
| **Gateway** | 路由、全局过滤器、统一鉴权入口 | JWT 鉴权收敛到网关，下游不重复校验（或二次校验策略清晰） |
| **Sentinel** | 限流、熔断、降级、热点规则 | 压测时能拦住流量，下游故障不拖垮整站 |

### 3.2 拆分原则（先小后大）

建议按「业务边界」拆，而不是按技术层硬拆：

1. **用户/认证服务**：登录、用户、角色权限（对接现有 RBAC 笔记）
2. **业务服务**：设备/订单/巡检等核心域（按你真实项目选一个）
3. **可选：通知/任务服务**：异步消息、定时任务

先保证：**网关 → 业务服务 →（Feign）用户服务**，链路通即可。

### 3.3 阶段项目

把现有 Spring Boot 单体（或巡检/物联网后台）拆成：

- `gateway`
- `user-service`
- `biz-service`

全部注册到 Nacos，配置外置，网关统一鉴权 + 一条限流规则。

### 3.4 本阶段产出笔记建议

放在本目录后续可拆文件：

- `Nacos服务注册与配置.md`
- `OpenFeign远程调用.md`
- `Gateway网关与鉴权.md`
- `Sentinel限流熔断.md`

## 四、阶段 2：MQ 深度 + 分布式一致性（3～4 周）

> **目标**：会做异步解耦，且能讲清丢失、重复、乱序、积压怎么处理。

### 4.1 MQ（RocketMQ / RabbitMQ 二选一，主学其一）

| 主题 | 必须掌握 |
|------|----------|
| 投递可靠性 | 生产者确认、失败重试、本地落库再发 |
| 消费可靠性 | 手动 ACK、幂等键、消费失败重试、死信队列 |
| 常见故障 | 重复消费、消息丢失、顺序消息边界、积压排查 |
| 业务场景 | 削峰、解耦、延时消息、事务消息（了解） |

### 4.2 分布式一致性（先业务方案，再框架）

优先级建议：

1. **本地消息表 / Outbox（首选落地）**：业务库同事务写消息 → 定时/CDC 投递 → 消费方幂等  
2. **最终一致性状态机**：订单状态流转可回放、可补偿  
3. **Seata AT**：了解原理与适用边界，能答面试；生产要评估侵入与运维成本  
4. **TCC / SAGA**：知道适用高一致、长事务场景即可，不必一上来深挖源码

### 4.3 阶段项目

串一条完整链路：

```
下单 → 扣库存(Redis/DB) → 写本地消息 → MQ → 通知/积分服务消费（幂等）
```

对照你已有的秒杀 / Redis / RBAC 笔记，把「鉴权 + 缓存 + 异步」合进同一条业务流。

### 4.4 本阶段产出笔记建议

- `MQ可靠性与幂等.md`
- `本地消息表与最终一致性.md`
- `Seata模式对比.md`（了解向）

## 五、阶段 3：JVM 排查能力（穿插 2 周，不要当主线闷学）

> **目标**：从「背过概念」升级到「线上能定位」。

### 5.1 必会清单

| 主题 | 通关标准 |
|------|----------|
| 运行时数据区 | 能对照堆、栈、元空间解释一次 OOM |
| GC | 知道 G1 适用场景；能读懂基础 GC 日志 |
| 常用参数 | `-Xms/-Xmx`、元空间、直接内存有基本概念 |
| 排查工具 | `jps` / `jstack` / `jmap`；Arthas 常用命令（thread、dashboard、watch） |
| 典型故障 | CPU 飙高、线程死锁、内存泄漏、Full GC 频繁 |

### 5.2 学习方式

- 每周跟一个线上模拟题：故意造一次 CPU 高 / 内存涨，用工具定位  
- 结合阶段 1 的服务压测一起练，比单独啃《深入理解 JVM》全书更高效  
- 已有 `基础/JVM基础.md` 可当提纲，进阶重点补「工具 + 案例」

### 5.3 本阶段产出笔记

- ✅ `jvm排查/diagnostic-lab实操与JVM原理.md`（三场景实操 + 原理）
- ✅ `jvm排查/jvm-dump-usecases实操教程.md`（扩展病例库）
- 待写：`Arthas常用命令速查.md`

## 六、阶段 4：可观测与云原生（3～4 周）

> **目标**：服务挂了知道在哪挂、慢在哪、怎么扩。

### 6.1 可观测三件套

| 维度 | 选型建议 | 通关标准 |
|------|----------|----------|
| 指标 | Prometheus + Grafana | 接口 QPS、延迟、错误率有面板 |
| 日志 | Loki 或 ELK（会其一） | 按 traceId / 订单号能串日志 |
| 链路 | SkyWalking 或 OpenTelemetry | 跨服务调用链可见，能找慢 span |

### 6.2 Kubernetes 基础（在 Docker 已会的前提下）

- Pod / Deployment / Service / ConfigMap / Secret / Ingress  
- 滚动更新、探针、资源限制  
- 把 docker-compose 里的微服务迁一套最小 K8s 清单即可，不必一上来学 Service Mesh

### 6.3 阶段项目

微服务 + MQ 项目：

1. 接上 SkyWalking  
2. Grafana 看 QPS / 错误率  
3. 部署到 K8s（本地 kind/minikube 或云上任一环境）

## 七、阶段 5：架构拓展（按需，不抢主线）

有余力再上，避免同时开太多坑：

| 方向 | 何时学 | 学到什么程度 |
|------|--------|--------------|
| Elasticsearch | 业务有搜索/日志检索需求 | 索引、DSL、聚合、和业务同步方案 |
| ShardingSphere | 单表真的顶不住时 | 读写分离或水平分片跑通一次 |
| DDD / 事件驱动 | 服务越拆越乱时 | 限界上下文、聚合；CQRS 了解即可 |
| WebFlux / 虚拟线程 | 有高并发 IO 瓶颈时 | 会选型、会对比阻塞模型即可 |
| 灰度 / 多活 | 团队有多环境发布需求 | 概念清晰，能画架构图 |

## 八、4 周启动计划（立刻可执行）

适合「先跑起来」的最短路径：

| 周次 | 主题 | 本周必做 |
|------|------|----------|
| 第 1 周 | Nacos + 拆服务 | 单体拆出 user / biz，注册到 Nacos，配置外置 |
| 第 2 周 | Feign + Gateway | 跨服务调用通；网关路由 + JWT 鉴权 |
| 第 3 周 | Sentinel + 压测 | 一条限流、一条熔断；简单压测看效果 |
| 第 4 周 | MQ 可靠性雏形 | 下单发消息 + 消费幂等 + 失败进死信（或重试表） |

第 4 周起每周穿插半天 JVM/Arthas，不单独排整月。

## 九、学习与笔记约定

1. **一个组件一份笔记**：原理 → 最小可运行配置 → 踩坑 → 面试口述稿（3 分钟版）  
2. **每个阶段必须有可运行项目**，纯看文档不算完成  
3. **面试口述优先于源码细节**：先能讲清链路与取舍，再按需下潜源码  
4. **与现有笔记联动**：RBAC、Redis 锁、秒杀、SQL 优化继续复用，进阶项目里「嵌进去」而不是重写一套理论  
5. **选型克制**：MQ 只深耕一种；注册中心以 Nacos 为主；事务先 Outbox 再 Seata
