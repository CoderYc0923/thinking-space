- 第一优先级，先**恢复可用性**
  - **切流**
- 流量稳住后再看监控、日志、GC、线程、依赖等做问题定界和处理





- 和重启的区别

  - |      | 切流                     | 重启                 |
    | :--- | :----------------------- | -------------------- |
    | 目的 | 马上让用户还能用         | 尝试恢复坏实例       |
    | 速度 | 秒～分钟级（看准备度）   | 可能更慢，且可能再挂 |
    | 前提 | 早有多集群/多活/降级预案 | 单点时只能硬扛       |



- **切流**

  - 就是在接入层/调度层将流量从故障单元切到健康单元或降级路径：网关摘流、LB调权重、多活切机房。同时配合限流保核心链路。

  - ```java
    用户 → 入口（DNS / 网关 / SLB） → 机房A / 集群A  ❌崩了
                                  ↘ 切到 → 机房B / 集群B / 降级页  ✅
    ```

  - 通常为：

    - **换活集群**：从坏实例/坏机房切到好的
    - **降量**：只放部分流量，或只保核心链路（下单/支付）
    - **降级**：非核心接口直接挡掉或返回兜底

  - 具体操作（从快到慢）：

    - **均衡负载/网关层**（最常见、最快）
      - `Nginx\SLB\Spring Cloud Gateway/Kong`
      - 把坏机器、坏机房的upstream摘掉权重/设为0
      - 或改路由规则：`/api/order`只打到健康集群
    - **注册中心 / 服务发现**
      - 实例标记下线、隔离、禁止被发现
      - 新流量不再打到故障Pod / 节点
      - 适用于某一个服务实例挂了
    - **多活 / 单元化 （大促标配叙事）**
      - 机房A崩了，把该单元流量切到机房B
      - 通过DNS、全局流量调度（GTM）、统一接入层切单元
    - **限流 / 熔断 / 降级**（常和切流一起做）
      - Sentinel / 网关限流：把洪峰挡住
      - 非核心（推荐、积分、弹幕）直接降级
      - 核心交易链路优先保
    - **功能开关 / 配置中心**
      - `Nacos / Apollo`改开关：关掉秒杀扩展、关掉复杂查询
      - 比发版快、属于【软切】能力
