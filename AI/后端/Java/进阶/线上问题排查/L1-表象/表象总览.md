# L1 用户表象：最先感知到什么

> 这一层**只用用户/业务语言**。  
> 不要写 CPU、磁盘、GC、OOMKilled——那些是 [L2 信号](../L2-初步排查/初查清单.md)。

---

## 1. 五类用户表象（U1～U5）

| ID | 用户/业务怎么说 | 对外长什么样 | 常见伴随（仍算用户侧） |
|----|-----------------|--------------|------------------------|
| **U1** | 「打不开」「进不去」「服务没了」 | 完全不可用 / 页面打不开 / App 提示服务异常 | 探活失败、大面积无法访问 |
| **U2** | 「点了没反应」「一直转圈」「全超时」 | 请求卡住或大面积超时 | 成功率断崖，像假死 |
| **U3** | 「整体变慢」「比刚才卡」 | 还能用，但明显变慢 | P95/P99 升高，仍有成功 |
| **U4** | 「大量失败」「老报错」「下单失败」 | 错误/失败明显变多 | 5xx、业务错误提示暴涨 |
| **U5** | 「只有整点卡」「活动才挂」「一会儿好一会儿坏」 | 偶发或周期性 | 固定窗口、活动期、发版后一段时间 |

可多选，例如：**U2 + U4**（超时同时大量失败）、**U3 + U5**（平时慢一点，整点尖刺）。

---

## 2. 怎么选（决策）

```text
完全不能用、打不开了？          → U1
还能进，但大面积超时/没反应？    → U2
还能用，只是慢？                → U3
主要是失败/报错变多？            → U4
和「某个时间/活动/发版」强相关？ → 加上 U5（可与上面叠加）
```

| 你随口说的 | 勾选 |
|------------|------|
| 卡死 | **U2**（若已打不开 → **U1**） |
| 接口慢 | **U3**（若已大面积超时 → **U2**） |
| 进程没了导致打不开 | 用户侧仍是 **U1**；「进程没了」留给 L2 |
| P99 周期性尖刺 | **U3 或 U2** + **U5** |

---

## 3. 本层禁止 / 允许

**禁止写进 L1**

- CPU 打满、内存涨、磁盘满、写不了日志  
- Full GC、OOMKilled、线程池拒绝、启动失败  
- 「一定是死锁 / 慢 SQL」

**允许写进 L1**

- 用户原话、业务影响面（全站 / 单接口 / 单地区）  
- 故障时间窗  
- 是否「监控先告警、用户后投诉」（仍用 U 编码）

**本层输出示例**

```text
表象：U2 + U4
用户原话：下单一直转圈，部分直接失败
窗口：14:02～14:20
影响：下单/支付，其它浏览尚可
是否发版：未知（留给 L2）
```
