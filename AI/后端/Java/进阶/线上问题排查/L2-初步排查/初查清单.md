# L2 初查信号：监控 / 机器上看到什么 → 倾向模块

> 输入：[L1 用户表象 U1～U5](../L1-表象/表象总览.md)  
> 本层产出：信号编码 **S-\*** + 倾向模块 → [L3 分流](../L3-模块/00-模块分流.md)  
> 环境入口差异：[L4](../L4-环境/部署环境差异.md)

**L1 是用户话；L2 才是 CPU / 磁盘 / GC / 进程 / 依赖。**

---

## 0. 五～十五分钟剧本

```text
① 记下 L1：U?（用户怎么坏的）
② 是否刚发版 / 推配置？（S-REL）
③ 进程：在 / 反复重启 / 起不来 / 没了（S-PROC）
④ 箱子：CPU、内存、磁盘（S-CPU / S-MEM / S-DISK）
⑤ 报错原文：OOM？超时？拒绝？（S-ERR）
⑥ 依赖大盘：DB / Redis / 下游红不红？（S-DEP）
⑦ 需要时：jstack ×2～3（S-THREAD）；GC 日志/jstat（S-GC）
⑧ 填表 → 倾向模块 → 进 L3
```

顺序口诀：**Box → 依赖 → Threads → GC → Heap（dump 最后）**。

---

## 1. 信号编码表（S-\*，原「机器侧 A～I」收编于此）

| 编码 | 信号（我们看到的） | 典型表现 | 常指向 |
|------|-------------------|----------|--------|
| **S-PROC** | 进程状态异常 | 没了、反复重启、CrashLoop、**起不来** | 应用内存/配置；依赖连不上；容器 limit |
| **S-CPU** | CPU 异常 | 打满 / 很低却超时 | 高→应用热点或 GC；低+卡→等锁/等池/等 IO |
| **S-MEM** | 内存 / 被杀 | 堆涨、RSS 涨、**OOMKilled**、Exit 137 | 堆/堆外/元空间/容器账 |
| **S-GC** | GC 异常 | FGC 狂、长停顿、`前M->后M`≈0 | 应用 JVM（泄漏/堆小/分配） |
| **S-DISK** | 磁盘 / 句柄 | 盘满、**写不了日志**、Too many open files | 日志/dump/FD 泄漏 |
| **S-ERR** | 报错原文 | OOM 类型、Rejected、Connection not available、StackOverflow | 按关键字分流模块 |
| **S-DEP** | 依赖异常 | DB/Redis/下游大盘红 | 数据库 / 中间件 |
| **S-REL** | 变更窗口 | 刚发版、推配置、扩缩容 | 偶发触发器 + 再定模块 |
| **S-THREAD** | 线程栈特征 | deadlock / getConnection / HttpClient / 死循环 | 应用 / 数据库 / 中间件 |
| **S-TIME** | 时间规律 | 整点、固定周期、仅活动期 | 偶发（常叠加其它 S） |

旧文档里的「启动失败、磁盘满、CPU 飙高、Full GC」等，全部是上表信号，**不是 L1**。

## 3. L1 × 信号 → 模块（决策核心）

| 用户表象 | 优先采的信号 | 若信号如此… | 倾向 |
|----------|--------------|-------------|------|
| **U1** 不可用 | S-PROC、S-ERR、S-DEP、S-REL | 起不来 + 连不上配置中心/DB | 中间件/数据库 + 配置 |
| | | 反复重启 + OOMKilled/137 | 应用内存 + L4 容器账 |
| | | 所有实例一起挂 + 依赖红 | 数据库/中间件 |
| **U2** 卡死/大面积超时 | S-CPU、S-THREAD、S-DEP | CPU 低 + 栈在 getConnection | **数据库** |
| | | CPU 低 + 栈在 HttpClient/Redis | **中间件** |
| | | deadlock / 死循环 | **应用-JVM** |
| | | 线程池拒绝（S-ERR） | **应用-JVM**（常被 DB/下游拖满） |
| **U3** 变慢 | 拆 RT + S-GC + S-DEP | DB RT 占比高 | **数据库** |
| | | 下游占比高 | **中间件** |
| | | 与 GC 停顿对齐（S-GC） | **应用-JVM** |
| | | 周期性（S-TIME） | **偶发** + 再查 GC/任务 |
| **U4** 大量报错 | S-ERR、S-DEP、S-REL | 依赖超时/连不上 | 数据库/中间件 |
| | | NPE/业务码 + 刚发版 | 偶发（发布）/ 应用 Bug |
| | | RejectedExecution | 应用线程池 |
| **U5** 偶发/时段 | S-TIME 必做时间线 | 整点任务 / 大促 / 发版 | **偶发**，再追到具体模块 |

## 4. 初查命令包（Linux）

### 4.1 S-PROC / 箱子

```bash
ps -eo pid,etime,pcpu,pmem,rss,cmd | grep -E 'java|你的服务'
uptime
df -h
dmesg -T | tail -50 | grep -iE 'oom|killed process'
```

### 4.2 探活与排队（U1/U2 常用）

```bash
curl -m 3 -s -o /dev/null -w '%{http_code} time=%{time_total}\n' http://127.0.0.1:8080/actuator/health
ss -s
```

### 4.3 S-ERR 日志

```bash
grep -E 'OutOfMemoryError|GC overhead|Too many open files|RejectedExecution|Connection is not available|timed out|StackOverflow' -n app.log | tail -50
```

### 4.4 S-THREAD

```bash
PID=$(pgrep -f '你的jar' | head -1)
jstack "$PID" > /tmp/jstack-1.txt
sleep 15
jstack "$PID" > /tmp/jstack-2.txt

grep 'Found one Java-level deadlock' /tmp/jstack-1.txt
grep -nE 'HikariPool|getConnection|okhttp|feign|httpclient' /tmp/jstack-1.txt | head
grep 'Thread.State' /tmp/jstack-1.txt | sort | uniq -c | sort -rn
```

高 CPU（S-CPU）对齐线程：

```bash
top -Hp "$PID" -n 1 | head -20
printf '%x\n' <十进制TID>
grep -A 30 'nid=0x...' /tmp/jstack-1.txt
```

### 4.5 S-GC / S-MEM

```bash
jstat -gcutil "$PID" 1000
jcmd "$PID" GC.heap_info
# GC 日志（平时应已开启）
tail -100 /var/log/app/gc.log
# 看：Pause 是否极勤；63M->62M(64M) 是否回收≈0

# dump 最后上、高峰慎用
# jcmd "$PID" GC.heap_dump /data/dump/heap.hprof
```

### 4.6 S-DISK / FD

```bash
df -h
ls /proc/$PID/fd 2>/dev/null | wc -l
lsof -p "$PID" 2>/dev/null | wc -l
ulimit -n
```

### 4.7 本机 Windows 练习

```powershell
$jdk = "D:\Java\jdks\jdk-21.0.11_10\bin"
& "$jdk\jps.exe" -l
& "$jdk\jstat.exe" -gcutil <pid> 1000
& "$jdk\jstack.exe" <pid> | Out-File -Encoding utf8 .\jstack-1.txt
```

## 5. 第一证据速查

| 主要信号 | 优先采证 | 同时看 |
|----------|----------|--------|
| S-PROC 起不来/重启 | 启动日志、Exit/OOMKilled | 依赖、limit |
| S-THREAD + U2 | jstack ×2～3 | 连接池、依赖 |
| S-DEP 红 | 依赖控制台/APM | 本机是否被拖死 |
| S-GC / S-MEM | GC 日志、jstat；再考虑 dump | 容器 limit、RSS |
| S-DISK | df、FD 计数 | 日志切割、dump 残留 |
| S-TIME | 时间线表（任务/GC/流量/发布） | 再回其它 S |
