# L3 模块分流

> 输入：L1 的 **U\*** + L2 的 **S-\***  
> 输出：进入四个模块之一（可并行，先查概率高的）

---

## 1. 分流图

```text
 L2 信号
   │
   ├─ S-DEP 红 / S-THREAD 在 getConnection / 慢 SQL ──► 数据库/
   ├─ S-DEP 红 / S-THREAD 在 Redis·MQ·HttpClient ───► 中间件/
   ├─ S-ERR 含 OOM·Rejected·deadlock / S-GC / S-MEM / 死循环 ─► 应用-JVM/
   └─ S-TIME / S-REL（整点·大促·发版）──────────────► 偶发与特殊场景/
        （偶发多是触发器，对齐后仍回上面三类修根因）
```

---

## 2. 一句话决策

| 证据组合 | 打开 |
|----------|------|
| U2 + 栈在 Hikari getConnection | [数据库](./数据库/README.md) |
| U2/U3 + 栈在 Feign/Redis | [中间件](./中间件/README.md) |
| U1/U3 + OOM / FGC / deadlock / 线程泄漏 | [应用-JVM](./应用-JVM/README.md) |
| U5 或 S-REL/S-TIME 很强 | [偶发与特殊场景](./偶发与特殊场景/README.md) |
| 仍不确定 | 回 [L2](../L2-初步排查/初查清单.md) 补 jstack + 依赖大盘 |

---

## 3. 边界

| 模块 | 负责 | 注意 |
|------|------|------|
| 应用-JVM | 进程内代码、线程、堆、GC、本地 FD/池 | 栈在 DB 客户端时先数据库 |
| 数据库 | SQL、锁、库连接、RDS | 应用没 close 连接要两边查 |
| 中间件 | Redis/MQ/下游/注册配置 | DNS/网络可先当超时再查 L4 |
| 偶发 | 时间/活动/发布触发 | 日常必现缺陷归上面三类 |
