# 线上问题排查（分层笔记）

> **层级原则**：最外层必须是**用户/业务先感知到什么**；机器打满、写不了日志、GC 尖刺等是排查时采到的**信号**，不是第一表象。  
> **JVM 动手练手**：[../jvm排查/](../jvm排查/)

---

## 分层总览（请按这个想）

```text
 L1 用户表象（最先）
   不可用 · 卡死/大面积超时 · 变慢 · 大量报错 · 偶发/某时段才出问题
   —— 用户怎么说、业务怎么坏；还没有 CPU/磁盘 这类词
        │
        ▼
 L2 初查信号（打开监控 / 登机器后看到什么）
   进程 · CPU · 内存/OOMKilled · GC · 磁盘/FD · 报错原文 · 依赖 · 发版 · 线程栈
   —— 用信号表收敛「倾向哪个模块」
        │
        ▼
 L3 模块（问题落点）
   应用/JVM · 数据库 · 中间件/下游 · 偶发触发器（大促/发版/整点）
        │
        ▼
 L4 环境（同一结论，采证入口不同）
   单机 · 多机集群 · K8s/ACK · 阿里云 ARMS/RDS/SLS
```

**读法**

1. [L1 用户表象](./L1-表象/表象总览.md) —— 只用用户话术归类  
2. [L2 初查信号](./L2-初步排查/初查清单.md) —— 采信号、填表、指向模块  
3. [L3 模块分流](./L3-模块/00-模块分流.md) —— 下钻子问题与命令  
4. [L4 环境](./L4-环境/部署环境差异.md) —— 换成真实部署入口  

原则：[00-思维模型.md](./00-思维模型.md)

## 和旧「A～I」的关系

以前把「CPU 高、磁盘满、启动失败」和「用户卡死」写在同一层，**层级混了**。

- 用户侧 → 只留在 **L1（U1～U5）**  
- 机器/监控侧 → 全部收到 **L2（S-\* 信号）**  
- 旧字母表不再作为 L1 编码
