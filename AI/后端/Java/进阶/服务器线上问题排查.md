# 服务器线上问题排查（表象 → 可能原因）

> **定位**：先认准「表象」，再枚举可能根因；不要一上来就断定是 JVM。  
> **关联**：JVM 专项实操见 `jvm排查/diagnostic-lab实操与JVM原理.md`  
> **用法**：线上先对表象分类 → 对照本章可能原因缩小范围 → 再采对应证据（dump / SQL / 指标）

---

## 〇、怎么用这份笔记

```
现象（用户/监控看到什么）
  → 归入一类或两类表象
  → 对照「可能原因清单」做排除
  → 采最少证据验证（先看栈/池/慢 SQL，再决定是否 dump）
```

**原则**：

1. **表象 ≠ 根因**：卡死可能是死锁，也可能是 DB 连接池打满。  
2. **先外部依赖、再 JVM 内部**：很多「应用挂了」其实是 DB / Redis / 下游超时拖死。  
3. **同表象可叠加**：例如慢 SQL → 连接占满 → 接口超时 → 线程池打满，一条因果链。

---

## 一、表象总览（先背这张表）

| 表象（对外看到） | 常见监控信号 | 第一眼该看什么 |
|------------------|--------------|----------------|
| A. 内存涨 / OOM / 进程消失 | 堆使用持续抬升、OOM、cgroup OOMKilled | 堆曲线 + 是否进程被杀 + GC 是否跟得上 |
| B. 卡死 / 无响应 / 大面积超时 | 成功率骤降、RT 无穷大、线程池队列满 | Thread Dump + 连接池 + 下游/DB |
| C. 变慢（延迟升高） | P99 飙高、吞吐下降 | 慢 SQL / 下游 RT / GC 停顿 / 锁竞争 |
| D. CPU 飙高 | 机器/容器 CPU 打满 | 热点栈（profiler）vs GC 线程 vs 业务死循环 |
| E. 错误率飙升 | 5xx、业务异常、超时异常暴涨 | 异常栈 TOP + 依赖健康度 |
| F. 频繁 Full GC / 吞吐量塌 | GC 时间占比高、停顿尖刺 | GC 日志 + 分配速率 + 是否泄漏 |
| G. 磁盘 / 文件句柄相关 | 写失败、Too many open files、磁盘 100% | 日志量、临时文件、连接/FD 泄漏 |
| H. 启动失败 / 起不来 | 进程退出、健康检查失败 | 启动日志、配置、端口、依赖连不通 |
| I. 偶发抖动 / 周期性尖刺 | 某时段 P99 毛刺 | 定时任务、GC、缓存失效、流量波峰 |

下面按表象展开「可能原因」——尽量列全，排查时按概率从高到低排除即可。

## 二、A. 内存涨 / OOM / 进程消失

### 2.1 表象细节

- 堆使用锯齿抬升、回收后基线越来越高  
- `OutOfMemoryError: Java heap space` / `Metaspace` / `Direct buffer memory`  
- 进程突然没了（可能是 OOM Killer，不一定有 Java OOM 日志）  
- 容器 Restart、Exit 137（常见 cgroup 内存杀进程）

### 2.2 可能原因

#### JVM / 应用代码

| 原因 | 说明 |
|------|------|
| 堆内存泄漏 | 集合/缓存无限增长、监听器未移除、ThreadLocal 未清理 |
| 无界缓存 | 本地 Cache 无上限、无过期；Guava/Caffeine 配置不当 |
| 堆过小 | `-Xmx` 相对业务峰值不够；或负载上涨后未扩容 |
| 大对象 / 一次加载过多 | 超大 List、一次性读全表进内存、导出未分页 |
| 元空间泄漏 | 动态代理/热加载/脚本引擎反复生成类；`-XX:MaxMetaspaceSize` 过小 |
| 直接内存 / 堆外 | Netty/NIO DirectByteBuffer、未限制 `-XX:MaxDirectMemorySize` |
| 本地内存（非堆） | JNI、压缩包、某些驱动；堆看着不大但 RSS 暴涨 |
| 内存碎片 / 晋升失败 | 老年代碎片或分配失败触发 OOM（相对少见，看 GC 日志） |

#### 数据库 / 持久层

| 原因 | 说明 |
|------|------|
| 大结果集一次拉回 | `SELECT *` 无分页、报表查询打爆堆 |
| 连接池过大 | 每个连接有缓冲；池过大放大内存占用（通常不是主因，但是推手） |
| ORM 一级/二级缓存 | Session/二级缓存囤积过多实体 |
| Blob/大字段 | 大文本、图片字段整行加载 |

#### 中间件 / 缓存 / MQ

| 原因 | 说明 |
|------|------|
| Redis 大 Value 反序列化 | 一次拉超大 key、pipeline 批量过大 |
| MQ 消费堆积后批量拉取 | 单次 pull 消息过多、消息体过大 |
| HTTP 客户端缓冲 | 下载大文件全进内存、响应体未流式处理 |

#### 系统 / 容器

| 原因 | 说明 |
|------|------|
| 容器内存 < 堆+元空间+堆外+线程栈 | 堆内没 OOM，被 cgroup OOMKill |
| 线程过多 | 每线程栈（如 1MB）× 线程数 → RSS 涨 |
| 宿主机内存争抢 | 同机多进程；swap 颠簸后表现异常 |

### 2.3 鉴别要点（极简）

- 有 Java OOM 日志 → 看是 heap / metaspace / direct  
- 无 Java OOM、Exit 137 → 优先查容器 limit 与 RSS  
- 堆基线持续抬升 → 泄漏嫌疑，做 Heap Dump  
- 偶发尖刺后能回落 → 大查询/大对象嫌疑，查那段时间的 SQL/接口

## 三、B. 卡死 / 无响应 / 大面积超时

### 3.1 表象细节

- 接口全部或大面积超时，健康检查失败  
- 进程还在，CPU 可能不高  
- 线程池 Active≈Max、队列满、拒绝策略触发  
- 用户侧「点了没反应」

### 3.2 可能原因

#### JVM / 并发

| 原因 | 说明 |
|------|------|
| Java 死锁 | 多把 `synchronized`/`Lock` 环等待；`jstack` 可见 deadlock |
| 锁长时间不释放 | 持锁做 IO/RPC；其他线程全 BLOCKED |
| 线程池打满 | 核心业务池队列满，新任务进不来 |
| 死等（无超时） | `Future.get()`、`Lock.lock()`、join 无超时 |
| CountDownLatch/栅栏未放开 | 某线程异常退出，其余永久等待 |
| Finalizer / 引用队列堆积 | 少见，表现为回收/清理卡住（次要） |

#### 数据库（高频）

| 原因 | 说明 |
|------|------|
| **连接池打满** | 慢 SQL/事务长 → 连接不归还 → 业务线程堵在 `getConnection` |
| **连接泄漏** | 未 close / 异常路径未归还；池逐渐耗尽 |
| **行锁 / 表锁等待** | 长事务、`SELECT FOR UPDATE`、间隙锁；线程在 `socketRead` |
| **死锁（DB 层）** | InnoDB deadlock，事务回滚或卡住（看 DB 死锁日志） |
| **慢 SQL 占满连接** | 全表扫、缺索引、错误执行计划 |
| **事务过大 / 未提交** | 事务内调 RPC、事务跨时过长 |
| DB 自身不可用 | 主库挂、连接数上限、磁盘满、主从切换中 |

#### Redis / MQ / 下游 HTTP

| 原因 | 说明 |
|------|------|
| Redis 阻塞命令 / 大 key | `KEYS`、错误 Lua、热 key 打满连接 |
| Redis 连接池耗尽 | 与 DB 池同理 |
| MQ 消费阻塞 | 同步消费卡住、手动 ack 未提交 |
| 下游超时配置不合理 | 无超时或超时过长 → 线程全堵在 HTTP Client |
| 下游雪崩 | 依赖全挂，重试风暴占满本机线程 |

#### 网络 / 基础设施

| 原因 | 说明 |
|------|------|
| 网络分区 / DNS 异常 | 解析卡住、半开连接 |
| 防火墙 / 安全组变更 | 突发性连不上依赖 |
| 负载均衡摘除异常 | 流量打到坏实例，或全摘导致无后端 |
| 磁盘满导致写日志/临时文件阻塞 | 进程看似卡死 |

### 3.3 鉴别要点（极简）

Thread Dump 里看多数线程堵在哪：

| 栈特征 | 优先怀疑 |
|--------|----------|
| `HikariPool.getConnection` / Druid 等 | 连接池打满或泄漏 |
| `MysqlIO` / `socketRead` + SQL 相关 | 慢 SQL 或 DB 锁等待 |
| `waiting to lock` + Found deadlock | Java 死锁 |
| Feign/OkHttp/HttpClient 读超时相关 | 下游慢或超时配置问题 |
| 线程池队列满 + 大量 WAITING | 上游被压住，找真正占着 worker 的栈 |

## 四、C. 变慢（延迟升高，但未完全卡死）

### 4.1 表象细节

- P95/P99 升高，平均 RT 变差  
- 吞吐下降，但部分请求仍能成功  
- 可能伴随偶发超时，尚未到「全挂」

### 4.2 可能原因

#### 数据库（最常见）

| 原因 | 说明 |
|------|------|
| 慢 SQL | 缺索引、索引失效、隐式转换、函数包列 |
| 锁等待（未到死锁） | 行锁竞争、热点行更新 |
| 连接不够但仍能借到 | 排队等连接 → RT 变长 |
| 结果集过大 | 网络传输 + 反序列化变慢 |
| 统计信息过期 / 执行计划变差 | 「昨天还快今天突然慢」 |
| 主从延迟 | 读从库读到旧数据触发重试/补偿（业务层变慢） |

#### JVM

| 原因 | 说明 |
|------|------|
| Young GC 过于频繁 | 分配太快，停顿累计抬高延迟 |
| Full GC / 长停顿 | 尖刺型 P99 |
| 锁竞争 | 热点 `synchronized`、高并发单锁 |
| 日志同步刷盘过多 | 每请求打大量同步日志 |
| 正则/序列化热点 | JSON 过大、反射过多 |

#### 缓存 / 中间件

| 原因 | 说明 |
|------|------|
| 缓存击穿 / 穿透 / 雪崩 | 瞬时打到 DB |
| 缓存失效风暴 | 大 key 同时过期 |
| Redis 变慢 | 持久化 fork、内存碎片、慢查询 |
| MQ 堆积导致消费端压力 | 业务处理变慢、线程被占 |

#### 流量与容量

| 原因 | 说明 |
|------|------|
| 流量突增超容量 | 线程/连接/CPU 接近上限 |
| 定时任务与业务流量重叠 | 整点报表拖垮 |
| 限流/降级未生效 | 本该挡的流量进来了 |

#### 系统层

| 原因 | 说明 |
|------|------|
| CPU steal / 嘈杂邻居 | 云主机被抢占 |
| 磁盘 IO 打满 | 日志、swap、DB 同盘 |
| 上下文切换过高 | 线程过多 |

### 4.3 鉴别要点（极简）

- **应用 CPU 不高 + RT 高** → 优先等 IO：DB / 下游 / 锁等待  
- **应用 CPU 高 + RT 高** → 热点计算、锁自旋、GC、序列化  
- **周期性尖刺** → GC 日志时间点 vs 定时任务 vs 缓存过期

## 五、D. CPU 飙高

### 5.1 表象细节

- 容器/主机 CPU 接近 100%  
- 可能伴随 RT 升高，也可能「空转」业务无进展  
- 需区分：业务线程高 vs GC 线程高

### 5.2 可能原因

#### 应用代码

| 原因 | 说明 |
|------|------|
| 死循环 / 忙等 | `while(true)` 无 sleep；自旋锁过久 |
| 热点计算 | 复杂正则、加解密、压缩、大循环 |
| 频繁序列化/反序列化 | 大 JSON、Protobuf 热点 |
| 反射 / 动态代理过重 | 框架路径异常热 |
| Hash 碰撞 / 退化数据结构 | 极端输入导致 CPU 打满（相对少） |
| 正则灾难性回溯 | 特定恶意/异常字符串 |

#### JVM / GC

| 原因 | 说明 |
|------|------|
| GC 压力过大 | 分配太快，GC 线程占满 CPU |
| 频繁 Full GC | 堆过小或泄漏导致反复回收 |

#### 数据库 / IO 相关（间接）

| 原因 | 说明 |
|------|------|
| 不停重试失败请求 | 下游挂了还疯狂重试 → CPU + 连接压力 |
| 大结果集反序列化 | DB/Redis 拉回后 CPU 用于解析 |
| 压缩/加密落在应用侧 | 大字段处理 |

#### 系统

| 原因 | 说明 |
|------|------|
| 线程数暴涨 | 调度开销本身抬高 CPU |
| 病毒/挖矿（偶发） | 非业务进程占 CPU |

### 5.3 鉴别要点（极简）

- `top`/`pidstat` 看是 Java 进程还是别的  
- 对 Java：采样栈看是业务方法还是 `GC task thread`  
- **高 CPU + 低吞吐** 更像死循环/忙等；**高 CPU + 高分配** 更像 GC 压力

## 六、E. 错误率飙升

### 6.1 表象细节

- 5xx、业务错误码、超时异常、熔断打开  
- 成功率曲线断崖

### 6.2 可能原因

| 类别 | 可能原因 |
|------|----------|
| 依赖 | DB 连不上、Redis 超时、下游 5xx、MQ 发送失败 |
| 配置 | 错误的开关、错误的地址、密钥过期、连接串变更 |
| 发布 | 新版本 Bug、兼容性问题、灰度流量打到坏实例 |
| 数据 | 脏数据、空指针路径、枚举未覆盖、唯一键冲突暴增 |
| 容量 | 线程池拒绝、连接池超时、限流误杀、熔断误触发 |
| 超时 | 本服务超时 < 下游耗时；重试放大错误 |
| 权限/安全 | 证书过期、鉴权服务挂、防火墙误拦 |
| JVM | OOM 后部分请求失败；Full GC 过长触发超时（表现为错误） |

## 七、F. 频繁 Full GC / 停顿尖刺

### 7.1 表象细节

- GC 日志里 FGC 次数狂涨，或单次停顿数百 ms～数秒  
- 业务 RT 出现规律/无规律尖刺  
- 吞吐下降，CPU 可能偏高

### 7.2 可能原因

| 类别 | 可能原因 |
|------|----------|
| 分配 | 短命对象过多、循环内创建大对象、自动装箱风暴 |
| 泄漏 | 老年代基线抬升，回收无效 → 反复 Full GC |
| 堆配置 | `-Xmx` 过小；新生代比例不合理 |
| 大对象直接进老年代 | 频繁触发老年代回收 |
| 元空间膨胀 | 类加载过多引发相关回收压力 |
| 显式 `System.gc()` | 代码/库误调（可 `-XX:+DisableExplicitGC`） |
| 外部 | 一次性大查询制造分配尖峰（根因在业务/SQL，表象在 GC） |

> Full GC 频繁往往是「果」：背后可能是泄漏、堆小、或业务分配失控（含 DB 大结果集）。

## 八、G. 磁盘 / 文件句柄相关

### 8.1 表象细节

- 写日志失败、上传失败、`No space left on device`  
- `Too many open files`  
- 进程异常、NIO 失败

### 8.2 可能原因

| 类别 | 可能原因 |
|------|----------|
| 磁盘满 | 日志未切割、heap dump 残留、临时文件、核心转储 |
| FD 泄漏 | 流/Socket/文件未关闭；连接泄漏也会占 FD |
| ulimit 过小 | 容器/进程句柄上限不够 |
| inode 耗尽 | 大量小文件（少见但难查） |
| DB 同机部署 | 数据库把盘打满拖垮应用（架构问题） |

## 九、H. 启动失败 / 起不来

### 9.1 可能原因

| 类别 | 可能原因 |
|------|----------|
| 配置 | 缺环境变量、YAML 写错、profile 不对 |
| 端口 | 端口被占用 |
| 依赖 | 启动时强依赖 DB/配置中心/注册中心连不上 |
| 资源 | 权限不足、目录不存在、密钥文件缺失 |
| JVM | 堆参数超过容器 limit，启动即被杀 |
| 迁移/发布 | 镜像错、JDK 版本不兼容、类冲突 |

## 十、I. 偶发抖动 / 周期性尖刺

### 10.1 可能原因

| 类别 | 可能原因 |
|------|----------|
| 定时任务 | 整点对账、全量刷新缓存、报表 |
| GC | 定期 Full GC、或分配随流量周期变化 |
| 缓存 | 批量过期、热点重建 |
| 流量 | 活动整点、爬虫波峰 |
| 基础设施 | 备份、快照、自动扩缩容、节点漂移 |
| DB | 统计信息自动更新、备份锁、高峰锁竞争 |

## 十一、跨表象因果链（很常见）

线上往往不是单点，而是链条：

```
慢 SQL / 行锁
  → 连接长时间占用
  → 连接池打满
  → 业务线程堵在 getConnection
  → Tomcat/业务线程池打满
  → 接口大面积超时（表象 B/C）
  → 调用方重试
  → 流量放大，更慢（雪崩）
```

```
无界缓存 / 大结果集
  → 堆涨（表象 A）
  → Full GC 频繁（表象 F）
  → P99 尖刺（表象 C）
  → 超时变多（表象 E）
```

```
下游无超时
  → 线程逐渐占满（表象 B）
  → CPU 未必高
  → 看起来像「应用卡死」，根因在下游
```

排查时问自己：**当前看到的是链条的哪一环？**

## 十二、按表象选「第一证据」（实操入口）

| 表象 | 优先采证 | 同时扫一眼 |
|------|----------|------------|
| A 内存/OOM | GC 曲线 + Heap Dump（确认泄漏后再上 MAT） | 容器 limit、RSS、是否 Exit 137 |
| B 卡死/无响应 | **Thread Dump（连续 2～3 次）** + 连接池指标 | DB 进程列表/锁等待、下游成功率 |
| C 变慢 | 慢 SQL、接口依赖 RT 拆分、GC 停顿 | 线程栈抽样、缓存命中率 |
| D CPU 高 | 采样 profiler / `Async Profiler` / Arthas `profiler` | 是否 GC 线程、是否死循环 |
| E 错误率 | 异常栈聚合 TOP N | 发布记录、依赖大盘 |
| F Full GC | GC 日志（GCeasy 等） | 分配来源、是否泄漏 |
| G 磁盘/FD | `df`/`lsof`/日志体积 | dump 残留、临时目录 |
| H 启动失败 | 启动日志全文 | 配置、端口、依赖连通 |
| I 抖动 | 对齐时间线：任务/GC/流量/发布 | 缓存过期策略 |

## 十三、一句话口诀

1. **先分类表象，再列可能原因，别先骂 JVM。**  
2. **卡住先看线程栈堵在哪；变慢先拆 RT（DB / 下游 / 本地）。**  
3. **内存先分清：堆 OOM、堆外、还是容器杀掉。**  
4. **DB 三件套：慢 SQL、锁等待、连接池，能解释大量「假 JVM 问题」。**  
5. **怀疑链条，不要只治最后一环。**
