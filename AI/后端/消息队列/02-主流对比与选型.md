# 02 · 主流 MQ 对比与选型

> 对比抓 **吞吐、延迟、堆积、事务、顺序、运维生态**。没有银弹，只有场景匹配。
>
> 流式处理：持续事件计算、类似实时的
>
> 批处理：定点计算，攒一批计算
>
> `AMQP`：`Advanced Message Queuing Protocol`高级消息队列协议，是消息中间件的开放标准，规定了客户端和`Borker`怎么通话（交换机、队列、路由、确认等），`RabbitMQ`常用。`Kafka`用`Kafka`协议，`RocketMQ`等用`Remoting/gRPC`等

---

## 一、一览表

| 维度 | RabbitMQ | Kafka | RocketMQ | Redis Stream |
|------|----------|-------|----------|--------------|
| 定位 | 通用业务消息 | 高吞吐日志/流 | 业务消息（电商金融向） | 轻量队列/已有 Redis |
| 吞吐 | 万～十万级 | **百万级** | 十万级 | 十万级（内存向） |
| 延迟 | **很低** | 低～毫秒级可调 | 毫秒级 | 很低 |
| 堆积 | 一般（队列模型） | **极强**（磁盘日志） | 强 | 受内存限制 |
| 事务消息 | 不支持（有确认/事务通道但非业务半消息） | 生产者幂等+事务（偏流） | **原生事务消息** | 无 |
| 顺序 | 单队列有序 | **分区内有序** | Queue 内有序 + 顺序消费 | 大体有序 |
| 延迟消息 | TTL+DLX / 插件 | 无原生 | **支持** | 需自己做 |
| 重试/死信 | 成熟 | 需自行设计 | **成熟** | 需自行设计 |
| 协议/生态 | AMQP，多语言好 | 大数据/流生态强 | Java/阿里云友好 | Redis 客户端即可 |
| 运维复杂度 | 中 | 中高（集群/副本） | 中 | 低（但别当海量堆积库） |

## 二、架构直觉（选型时有用）

### RabbitMQ

```text
Producer → Exchange（路由）→ Queue → Consumer
```

- 路由灵活（direct / topic / fanout）  
- 适合：复杂路由、传统企业异步、中等流量  
- 不适合：超大堆积、超高吞吐日志总线  

### Kafka

```text
Producer → Topic(分区日志) → Consumer Group（各持 offset）
```

- 顺序写磁盘、批量、零拷贝 → 吞吐王  
- 适合：日志采集、事件总线、流计算、大数据管道  
- 业务「延时消息 / 丰富重试」要自己补  

### RocketMQ

```text
Producer → NameServer / Proxy → Broker(Topic→Queue) → ConsumerGroup
```

- 业务特性全：事务、延时、重试、过滤  
- 适合：订单、支付、电商交易链路（国内阿里云常见）  
- 深挖见：[消息队列详解-RocketMQ版.md](./消息队列详解-RocketMQ版.md)  

### Redis Stream

- 已有 Redis、流量不大、要简易消费者组时可用  
- 持久化与堆积能力弱于专用 MQ；别扛大促主干道

## 三、选型决策树（实用版）

```text
主要是海量日志 / 流式计算 / 事件溯源？
├── 是 → Kafka
└── 否 → 业务异步、交易向？
         ├── 需要事务消息 / 延时 / 开箱重试
         │     → RocketMQ（尤其 Java + 阿里云）
         ├── 路由复杂、多语言、中等流量
         │     → RabbitMQ
         └── 极轻量且已有 Redis、可接受丢/限流
               → Redis Stream / 甚至 List（更弱）
```

同一家公司也可以 **Kafka（数据面）+ RocketMQ/Rabbit（业务面）** 并存。

## 四、云上常见形态（实操相关）

| 云产品方向 | 对应开源近似 |
|------------|--------------|
| 阿里云 RocketMQ | RocketMQ |
| 阿里云 Kafka / 开源自建 | Kafka |
| 阿里云 RabbitMQ / AMQP | RabbitMQ |
| 云上「轻量消息」 | 各厂商托管，概念仍是 Topic/队列 |

托管后少操心 Broker 磁盘与副本，但 **堆积、幂等、顺序、监控** 责任仍在业务侧。

---

## 五、特性速记（面试 30 秒版）

| MQ | 一句话 |
|----|--------|
| Kafka | 高吞吐日志型总线，分区内有序，生态偏流处理 |
| RocketMQ | 业务向，事务/延时/重试强，国内交易链路常见 |
| RabbitMQ | AMQP 通用、路由灵活、延迟低，吞吐与堆积非最强 |
| Redis Stream | 轻量，沾 Redis 运维，不适合当超大堆积中枢 |
