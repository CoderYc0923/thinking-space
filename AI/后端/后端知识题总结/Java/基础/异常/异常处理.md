异常处理方式：

- `try-catch`（可选`finally`/ `try-with-resources`）

  - `try`里某行抛异常，后面代码不执行，直接跳到匹配的`catch`

  - 多个`catch`按书写顺序匹配，子类要写在父类前面，比如`FileNotFoundException`在`IOException`前面，反了就编译报错。

  - Java7+可用多异常合并：`catch(IOException | SQLException e)`e实际是final的公共父类型语义

  - 没有匹配的`catch`会继续向上层调用栈冒泡

  - `catch`里处理完后，会继续执行`try-catch`后面的代码

  - `catch`里可以再`throw`：原样抛，包装成业务异常再抛都行、

  - `finally`代表`try`中不管成不成功都执行（除非System.exit()，JVM崩了，所在线程被杀了）`try`中`return`前会先跑`finally`；`finally`若也`return`，会覆盖`try`中`return`

  - `try-with-resources`，**离开try时按声明逆序自动close，不必手写finally关流**

    - 资源类要实现`AutoCloseable`(`Closeable`也行)

    - 关闭资源时若要再抛异常，会挂到主异常的`suppressed`（被抑制异常）上，可用`e.getSuppressed`看

    - 资源关闭优先`try-with-resources`，而不是裸`finally`

    - ```java
      try(InputStream in = new FileInputStream("a.txt");OutputStream out = new FileOutputStream("b.txt")) {
          // 用in / out
      } catch (IOException) {
          
      }
      ```

- `throw `/ `throws`

  - `throw`

    - 主动抛出一个异常对象，一次一个

    - 抛出**受检异常**： 本方法必须`catch`，或者方法签名`throws`

    - 抛出**非受检异常**`RuntimeException` / `Error`：编译器不强制`throws`

    - 常见用法：参数校验失败、业务规则不满足、把底层异常包装成统一业务异常再抛

    - ```java
      if (user == null) {
          throw new IllegalArgumentException("user 不能为null");
      }
      throw new IOException("读文件失败"); // 受检异常：本方法要catch或throws
      ```

    - 

  - `throws`

    - 写在**方法签名**上，声明可能要往外冒这些异常，可声明多个，用逗号分隔
    - 含义：代表这些异常不在这里处理，调用方要么再`catch`要么继续`throws`
    - **受检异常**往外传时，编译器强制一路声明或捕获，直到某层处理掉
    - **非受检异常**一般不必写`throws`，写了也没事，当提示
    - 重写父类方法时：子类`throws`的受检异常不能比父类**更宽**（不能抛父类没声明的新受检异常类型）



什么时候可以不写`throws`？

- 异常是**非受检异常**（`RuntimeException`或`Error`）
- 异常被本方法`catch`捕获处理了
- 根本不会产生需要声明的受检异常



执行顺序

- 进`try`，按书写顺序执行代码
- 某行有异常，去匹配`catch`，找到则执行该`catch`
- 若有`finally`则执行`finally`的逻辑
- 异常被`catch`消化，则继续`try-catch-finally`后的代码
- 异常没接住（或又被抛出），异常沿着当前线程的调用栈往上冒泡，直到某层被接住或该线程以未捕获异常结束
