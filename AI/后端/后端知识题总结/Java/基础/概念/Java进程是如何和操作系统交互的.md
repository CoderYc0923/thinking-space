**总结**

- Java 跑在 **JVM 进程**里，日常计算和对象分配主要在 JVM 内完成。
- 一旦需要操作系统资源（申请/扩展内存、线程、文件、网络等），路径是：  
  **Java 标准库 API → JVM → JNI/native → 系统调用 → OS → 硬件**，结果再回传。
- JVM 做跨平台与托管（GC、类加载等），OS 做真正的资源管理。

**交互路径**

```
Java 代码 → 标准库 API → JVM → JNI/native → 本地代码/系统调用 → OS → 硬件
```

**为什么不直接调 OS？**

- 为了跨平台：同一套字节码，换「该平台的 JVM + 本地适配」即可，业务代码不用写各 OS 的 syscall。

**和 C 进程差别？**

- C 常直接 syscall；Java 多一层 JVM，多了 GC、运行时、类加载等托管能力，也多一层开销。

**NIO / Netty？**

- 仍是这条交互路径，只是用非阻塞 + Selector 多路复用，用更少线程管理更多连接。
