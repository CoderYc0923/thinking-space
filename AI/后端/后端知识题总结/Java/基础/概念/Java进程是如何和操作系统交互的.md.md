**总结**

- Java跑在JVM进程中，日常计算和对象分配主要在JVM内完成；一旦需要操作系统资源（内存扩容、线程、文件或网络等），就从JDK API进入JVM，再经过JNI/native落到系统调用，由操作系统OS访问硬件并返回结果。JVM做跨平台和托管，OS做真正的资源管理。

**交互路径**

- Java -> JVM -> JNI/native -> 本地代码（C/C++）系统调用 -> OS操作系统 ->硬件



为什么不直接调用OS?

- 为了跨平台，同一套字节码，换JVM/OS适配层就可以跨平台了。



和C进程差别？

- C常直接syscall；Java多一层JVM，多了GC、运行时、类加载等。



NIO/Netty？

- 还是这条交互路径，只是用非阻塞 + Selecto多路复用，用更少线程管理更多连接。
