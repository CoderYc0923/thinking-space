面向对象的特点

- 封装
  - 数据和方法绑定在一起，对外隐藏细节，只暴露接口
- 继承
  - 子类复用父类结构和方法，建立层次关系
- 多态
  - 同一接口，不同对象不同行为（编译时重载、运行时重写）



多态体现在哪

- 重载
  - 同名不同参，编译期决定调用哪个
- 重写
  - 子类覆盖父类方法，运行期按实际类型调用
- 接口实现
  - 接口引用指向不同实现类
- 向上向下类型转换
  - 子转父向上转型安全，父转子向下转型要先instanceOf确认类型



多态解决了什么

- 提高拓展性、复用性，少改旧代码就能加新行为

- 是策略模式、面向接口编程、依赖倒置、里氏替换、去掉冗余if-else的基础

- ```java
  Animal a = new Dog();
  a.sound();  // 编译期看 Animal，运行期跑 Dog.sound()
  ```

- ```java
  // 没有多态时
  if (type == "alipay") { /* 支付宝 */ }
  else if (type == "wechat") { /* 微信 */ }
  else if (type == "card") { /* 银行卡 */ }
  
  // 有多态时,策略模式
  public interface PayStrategy {
      void pay(int amount);
  }
  
  public class Alipay implements PayStrategy {
      public void pay(int amount) {
          System.out.println("支付宝支付: " + amount);
      }
  }
  
  public class WechatPay implements PayStrategy {
      public void pay(int amount) {
          System.out.println("微信支付: " + amount);
      }
  }
  
  payStrategy.pay();  // 不用再一长串 if
  // 新类型 = 新实现类，旧代码少动甚至不动
  ```

- ```java
  // 面向接口编程
  // 写业务时依赖 PayStrategy，不依赖 Alipay：
  // OrderService 里看不到 Alipay、WechatPay，只调用 payStrategy.pay()。
  public class OrderService {
      private final PayStrategy payStrategy;
      // 构造时传入具体实现（也可以 setter / Spring 注入）
      public OrderService(PayStrategy payStrategy) {
          this.payStrategy = payStrategy;
      }
      public void checkout(int amount) {
          payStrategy.pay(amount);  // 这里不写 if 支付宝/微信
      }
  }
  
  //  真正选微信还是支付宝：在外面决定
  // 方式 B：自己 new（最直观）
  // 用支付宝
  OrderService order1 = new OrderService(new Alipay());
  order1.checkout(100);
  // 用微信
  OrderService order2 = new OrderService(new WechatPay());
  order2.checkout(100);
  
  
  // 方式 C：按用户选择选实现（仍把 if 关在组装层）
  PayStrategy strategy = "wechat".equals(payType)
          ? new WechatPay()
          : new Alipay();
  OrderService orderService = new OrderService(strategy);
  orderService.checkout(100);
  ```

- ```java
  
  // 方式 A：Spring 注入（项目里最常见）
  // 配置或 @Primary / @Qualifier / 按 payType 从 Map<String, PayStrategy> 取 bean，决定注入微信还是支付宝
  
  // 先准备两个 Bean
  public interface PayStrategy {
      void pay(int amount);
  }
  @Service("alipay")
  public class Alipay implements PayStrategy {
      public void pay(int amount) {
          System.out.println("支付宝: " + amount);
      }
  }
  @Service("wechatPay")
  public class WechatPay implements PayStrategy {
      public void pay(int amount) {
          System.out.println("微信: " + amount);
      }
  }
  
  // 写一个service
  @Service
  public class OrderService {
      private final Map<String, PayStrategy> payStrategyMap;
      
      // key = bean 名：alipay、wechatPay
      public OrderService(Map<String, PayStrategy> payStrategyMap) {
          this.payStrategyMap = payStrategyMap;
      }
      
       public void checkout(String payType, int amount) {
          PayStrategy strategy = payStrategyMap.get(payType);
          if (strategy == null) {
              throw new IllegalArgumentException("不支持的支付方式: " + payType);
          }
          strategy.pay(amount);
      }
  }
  
  // 调用
  orderService.checkout("alipay", 100);     // 走支付宝
  orderService.checkout("wechatPay", 100);  // 走微信
  
  
  
  
  
  
  ```

面向对象设计原则：

- SRP单一职责：一个类只干一类事情

- OCP开闭：对扩展开放，对修改关闭

- LSP里氏替换：子类可替换父类，行为不破坏约定

  - ```java
    // LSP：子类对象能替换父类对象，程序行为仍正确。
    void checkout(PayStrategy p) { p.pay(); }
    
    checkout(new Alipay());
    checkout(new WechatPay());  // 替换后仍能用
    // 要求子类别破坏父类/接口约定（比如不该抛奇怪异常、不削弱功能）。
    // 能替换的前提，正是多态：用父类型引用接子类对象。
    ```

  - 

- ISP接口隔离：接口要小而专，别强迫依赖用不到的方法

- DIP依赖倒置：依赖抽象，不依赖具体实现

  - ```java
    // DIP：高层不依赖低层细节，双方都依赖抽象。
    // 高层：OrderService
    // 抽象：PayStrategy
    // 低层：Alipay / WechatPay
    
    // 高层不 new Alipay()，只拿 PayStrategy。
    // 能这么干，是因为调用 payStrategy.pay() 时多态会进到真正的实现类。
    ```

  - 

- 最少知识：少跟陌生人说话，只和直接协作的对象交互







重载和重写

- 重载overload
  - 范围：同一类（也可父子类同名不同参）
  - 要求：方法名同，参数列表不同
  - 绑定：编译期
  - 目的：同名多用法
- 重写override
  - 范围：子类对父类
  - 要求：方法名、参数、返回类型兼容
  - 绑定：运行期
  - 目的：子类定制行为





抽象类和普通类

- 普通类可以new；抽象类不能直接实例化，用来被继承
- 普通类方法都可有实现；抽象类可有抽象方法（无方法体）+具体方法
- 继承规则一样：单继承、可实现多接口
- 抽象类常作为基类，抽公共逻辑



抽象类和接口

- 抽象类extends 单继承；接口implements，多实现
- 抽象类代表是什么；接口代表能做什么
- 抽象类可有实例变量、构造器、具体/抽象方法；接口可有常量`public static final`
- 抽象类方法可有实现；接口早期只能抽象，java8+可有default/static;java9+可有private



抽象类能加`final`吗？

- 不能，抽象要被继承，final禁止继承，冲突



抽象类能实例化吗？

- 不能直接 `new`。可以有构造器，但只在子类 `new` 时被 `super` 调用。



接口能有构造函数吗？

- 不能。接口不能 `new`，构造器无意义。



接口里可以有哪些方法？

- 抽象方法（默认 `public abstract`）
- `default` 方法（Java 8，有方法体，实现类可覆盖）
- `static` 方法（Java 8，用接口名调用）
- `private` 方法（Java 9，给 default 复用，实现类不可见）



静态变量 / 静态方法

- 属于类，不属某个实例；类加载时初始化，全实例共享一份
- 推荐用类名访问
- 静态方法：无实例也能调；不能直接访问非静态成员；不能被重写（只能隐藏）
- 场景：计数器、常量、工具方法（如 `Math`）



静态内部类 vs 非静态内部类

- 非静态内部类
  - 依赖外部类实例
  - 可直接访问外部实例成员
  - 先有外部类对象再创建
  - 一般不能随便定义静态成员（规则随版本有放宽）
- 静态内部类
  - 不依赖外部类实例
  - 直接访问静态成员；访问实例成员需外部类对象
  - 可独立创建
  - 可以有静态成员
- 非静态内部类为何能直接调外部方法？
  - 编译器给内部类偷偷加了一个指向外部类实例的引用（构造时传入），靠这个引用访问外部成员。
