两个事务

```sql
# 事务A
START TRANSACTION;
# TIME1
UPDATE students SET score=100 WHERE id=25;
# TIME3
INSERT INTO students(id, no, name, age, score)
VALUE (25,'S00025', 'S', 28, 90);

COMMIT;
```

```sql
# 事务B
START TRANSACTION;
# TIME2
UPDATE students SET score=90 WHERE id=26;
# TIME4
INSERT INTO students(id, no, name, age, score)
VALUE (26,'S00026', 'T', 23, 70);

COMMIT;
```

问：在RR隔离级别下，这两个事务执行会发生什么？

- 首先，先分析对应加锁状态
  - time1时，事务A的UPDATE操作会生成间隙锁，InnoDB会在数据中找到第一个大于25的主键作为锁住的右边界，所以锁住了(20,30)
  - time2时，事务B的UPDATE操作会生成间隙锁，InnoDB会在数据中找到第一个大于26的主键作为锁住的右边界，所以锁住了(20,30)。事务AB的间隙锁是不会互斥的。
  - time3时，事务A向表中插入id=25的记录，这会生成一个插入意向锁，同时阻塞等待事务B的间隙锁结束。
  - time4时，事务B向表中插入id=26的记录，这也会生成一个插入意向锁，同时阻塞等待事务A的间隙锁结束。
  - 而事务AB均需要结束事务才能释放锁，所以形成循环等待，产生死锁。

问：那如何解决呢？

- 可以先插入后更新，这样的话就不会产生插入意向锁。
