按范围分：全局锁、表锁、行锁

- 全局锁
  - flush tables with read lock 整库只读，常用于全库备份
  - 问题：全局锁整个数据库只读，备份期间业务只能读不能写，会造成业务停滞
  - 解决：若存储引擎支持可重复读的隔离级别，在备份数据库之前先开启事务， 会创建Read View。整个事务执行期间用的快照读，业务依旧可以对数据进行写操作。
  - 备份数据库的工具是mysqldump，在使用mysqldump时加上-single-transaction参数时，就会在备份数据库前先开启事务。
- 表锁
  - 表S锁（共享读锁） LOCK TABLES...READ
  - 表X锁（排他写锁）LOCK TABLES...WRITE
  - 元数据锁（MDL）
    - 不需要显示的使用 MDL，因为当我们对数据库表进行操作时，会自动给这个表加上 MDL
    - 对一张表进行 CRUD 操作时，加的是 **MDL 读锁**；
    - 对一张表做结构变更操作的时候，加的是 **MDL 写锁**；
    - 目的：CRUD 时不许改表结构，反之亦然
    - 事务提交才释放 → 长事务占着 MDL 读，DDL 拿不到写锁会堵；写锁等待时写优先于读，后续 CRUD 也会堵，可能把连接打满
  - 意向锁（InoDB表级）
    - 加行级 S 前先加表级 IS；加行级 X 前先加表级 IX
    - 普通 `SELECT` 快照读不加行锁；`LOCK IN SHARE MODE` / `FOR UPDATE` 才会
    - 意向锁之间不冲突；也不和行锁冲突；只和 `LOCK TABLES ... READ/WRITE` 这类表锁冲突
    - 作用：加表独占锁时不用扫全表看有没有行锁，看表上有没有 IX/IS 即可
  - AUTO-INC 锁
    - 自增主键赋值用；是特殊表锁，语句结束就释放（不是等事务提交）
    - 持锁期间别的插入会被堵，大批量插入影响并发
    - `innodb_autoinc_lock_mode`：
      - 0：传统 AUTO-INC，语句结束才放
      - 1（常见默认）：普通 insert 轻量快放；`INSERT…SELECT` 等批量仍等语句结束
      - 2：轻量锁，申请完自增值就放，并发最好；配 `binlog_format=ROW` 才安全，否则 `binlog_format=ROWstatement `下主从复制场景可能出现数据不一致
- 行锁：
  - MySQL行锁默认临键锁，但是在特定情况下会退化成记录锁（S\X）或者间隙锁
    - 等值查询且记录存在，退化成记录锁
    - 等值查询但记录不存在，在索引树找到第一条大于该查询记录的记录后，退化成间隙锁
    - 执行加锁语句时，若语句没走索引，会全表扫描聚簇索引，扫到的行会加上临键锁，相当于锁全表了。
    - 使用`select * from performance_schema.data_locks\G;`查看事务加了什么锁
      - 主要看的字段
        - LOCK_TYPE：锁类型
        - LOCK_MODE：锁模式
        - LOCK_STATUS：锁状态
        - LOCK_DATA：锁住的数据
  - 行S锁 SELECT ... LOCK IN SHARE MODE
  - 行X锁 SELECT ...FOR UPDATE\UPDATE\DELETE
  - 间隙锁 Gap LOCK
    - 锁开区间，不含记录本身
    - 主要用于RR（以及串行化），防止插入导致幻读
    - 间隙锁之间兼容（可同时持有重叠间隙），目的是挡插入
  - 临键锁 Next-Key Lock
    - 行锁加间隙锁，锁左开右闭(a,b]，锁记录又锁前面的间隙
    - 例：(3,5] → 不能插 4，也不能改 5
    - 含记录锁的时候，同范围X临键会互斥阻塞（也是就X锁互斥）
  - 插入意向锁
    - 行级特殊间隙锁
    - 插入前发现位置被间隙/临键占着，生成插入意向锁并等待
    - 与【占住该间隙的间隙锁】冲突；插入意向锁彼此可理解为锁【点】，间隙锁锁【区间】
