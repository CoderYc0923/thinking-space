- **InnoDB的数据是按照“数据页”为单位来读取的**

  - 一页的大小默认是16KB
  - 数据页的七个结构：
    - 文件头（File Header） 38字节：表示页的信息，其中有指针，把上下数据页串成**双向链表**（页与页逻辑连续）
    - 页头（Page Header） 56字节：表示页的状态信息
    - 最大、最小记录（Infimun、Supremum） 26字节：两个虚拟的伪记录，分别标识页中的最大、最小记录
    - 用户记录（User Records） 不确定：存放行记录内容（真正业务行 / 目录项都在这里，**行格式**）
    - 空闲空间（Free Space） 不确定：页中还没被使用的空间
    - 页目录（Page Directory） 不确定：存储用户记录的相对位置，对记录起到索引作用
    - 文件尾（File Trailer） 8字节：校验页是否完整
  - 数据页内包含用户记录，每个记录之间通过**行格式中的记录头部信息中的指针next_record**串成单向链表。
    - 单向链表插删方便，但检索最差要扫整条链
    - 所以，为了加快在数据页内高效查询记录，在数据页中设计了页目录，起到记录的索引作用。
  - 页目录存储各个槽（分组），且主键值是有序的，所以可以通过二分查找法的方式进行检索从而提高效率

- **B+树**

  - 当我们需要存储大量的记录时，需要多个数据页，这个时候就要考虑建立合适的索引才能方便定位记录所在的页。

    - 磁盘 IO 次数对效率很关键，所以用「矮胖」的 B+ 树：层数少 → IO 少，且利于范围查询

  - InnoDB 的 B+ 树

    - **每个节点都是一个数据页**
    - 只有叶子节点（最底层的节点）才存放「真正要查的数据内容」，非叶子节点（其他上层节点）仅用来存放目录项作为索引
    - 非叶子节点分为不同层次，通过分层来降低每一层的搜索量
    - 同一层节点按索引键有序，并用双向链表串起来，方便范围查询
  
  - 聚簇索引
  
    - 非叶子节点存主键值
    - 叶子节点存的是**完整行**（按上面的行格式编码）
    - 一个表只能由一个聚簇索引
    - 对应表空间里的「**数据段**」主要养的就是这棵树的叶子页
  
  - 二级索引
  
    - 非叶子节点存索引字段的值（如name）
  
    - 叶子节点存**索引列+主键值**
  
    - 一个表可以有多个二级索引
  
    - 在使用二级索引进行数据查询时，如果查询的数据能在二级索引找到，那就是**“索引覆盖”**
  
    - 如果查询的数据不再二级索引内，就需要通过二级索引的主键去聚簇索引获取数据行记录，这个过程就叫**“回表”**
  
    - **为什么需要二级索引？**
  
      - 因为聚簇索引是以主键值作为目录项来导航，但实际业务中，可能会出现按照其他列来进行查询，若在聚簇索引中就要全表扫描了。
      - 所以需要以其他列作为目录项导航的索引
  
    - 例如：
  
      - ```sql
        SELECT * FROM 'user' WHERE name = '张三'
        CREATE INDEX idx_user_name (name);
        ```
  
      - 
  
  - B+树快速查询主键记录
  
    - 从根页开始，用目录项二分，定位下一层该去哪一页。
    - 一层层往下，直到叶子页
    - 在叶子页的**页目录**里二分，落到某个槽
    - 顺着槽内记录的 `next_record` 单向链表，找到目标行
    - 按该表的**行格式**解析这一行的额外信息 + 真实数据，读出各列
