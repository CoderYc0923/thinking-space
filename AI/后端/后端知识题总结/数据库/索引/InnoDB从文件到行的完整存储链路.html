一页存不下一条大列时

触发条件 varchar / TEXT / BLOB 太大，当前数据页放不下整行（或策略要求外置）
页内真实数据区怎么留 留下 20 字节「溢出页地址」；真正大段字节放到溢出页链表里
溢出页本身 存剩余列数据；一页不够就再链下一张溢出页
Compact 页内：留部分列前缀 + 20B 溢出页地址；剩余进溢出页
Dynamic / Compressed 页内：通常只留 20B 地址；整列数据都在溢出页（5.7+ 默认 Dynamic）
②c 回滚段 undo 页集合 支撑回滚 + MVCC 读历史版本

undo 日志页（不是业务行页）

谁指向它 叶子行里的 roll_pointer（7B）指向本条记录的上一个版本
undo 记录存什么 UPDATE：旧值足够回滚/构造旧版本；INSERT：回滚时删掉即可的信息；DELETE：标记相关版本链信息
版本链 当前行 → undo1 → undo2 → … 形成版本链；一致性读按 Read View 沿链找可见版本
和数据页的区别 undo 页不组成用户表 B+ 树；purge 后可回收。溢出页存「大字段当前值」，undo 页存「历史版本」

上下层是怎么来的 不是手工分配，是页分裂长出来的

B+ 树的层，不是建表时预先画好的。一开始往往根页就是叶子； 数据变多、页写满发生 page split，父页多目录项，必要时才多出一层。

InnoDB 真实页分裂规则 叶 / 非叶同一套；先重排再裂；切法看插入方向

都不是「旧页原封不动 + 旁边挂空页」，而是把满页记录拆开；自增场景近似「左页留满、右开新页接着写」。

① 空间不够本页塞不下新记录

② 先 reorganize整理碎片空闲；够了就不裂
→
③ 仍不够 → split拆成两页 + 改同层双向链表
→
④ 改父目录加/调「键+子页号」；根满需加层则造新根

往最右递增
PAGE_RIGHT		 自增主键 旧页近乎满留下；右侧新开页接新行，后续更大键继续往最右页插 高（≈追加写）

下一条插哪？ 仍按索引键走目录项下钻，落在谁的键区间就进谁。自增总落最右叶；最右叶满再按「右偏分裂」开新页。
叶子 vs 非叶子 规则相同。叶拆的是用户行（或二级：键+主键）；非叶拆的是目录项。只有贴叶的那层非叶，子页号才是叶子页号。
和「区」无关 分裂 = 逻辑页怎么拆、树怎么改；区 = 物理按 64×16KB 申请空间。凑满 64 页不会自动加树高。
三句收束： ① 先重排，不行再裂。 ② 自增 ≈ 右偏分裂：左满、右开新页接着写（不是固定 50/50）。 ③ 随机插中间 ≈ 对半分 → 更费空间；故聚簇主键宜短且顺序。

树高 · 扇出 · 记录数估算 先分清：树能装多少 ≠ 单表该放多少

常说「一张表两千万左右」——多半是运维/业务经验阈值（备份、DDL、慢查、缓冲池）， 不是 B+ 树三层装不下。树高公式算的是「物理上大概还能挂多少行」。

约定 H根=叶→1；根→叶→2；根→非叶→叶→3
F ≈ 1000非叶扇出（bigint 主键粗算）
R一叶多少行 = 有效页空间 / 行长
N ≈ F(H−1) × R写满时的物理上限
有效页空间粗算 ≈ 15KB（16KB 扣页头尾/目录）
R ≈ 15KB / 平均行长　　F ≈ 1000
N ≈ F(H−1) × R　　非叶页数 ≈ (F(H−1) − 1)/(F − 1)（H=1 时为 0）
行长假设 R（行/叶） H=2 上限 H=3 上限 说明
偏瘦 ~200B ~80 ~8 万 ~8000 万 字段少、无大列
一般业务 ~500B ~30 ~3 万 ~3000 万 更贴近常见表；再打折就靠近「两千万」
偏宽 ~1KB ~15 ~1.5 万 ~1500 万 宽行 / 多索引列回表压力大
为什么口头常说「2000 万」 ① 行往往不止 200B，还要算二级索引占空间；② 随机键填充率常只有七成； ③ 备份、改表、刷脏、慢 SQL 在千万级就先痛了。 所以 ~2000 万是「该不该分表」的经验线，不是树高天花板。
怎么和公式对上 一般行 ~500B、H=3：N≈1000²×30=3000 万物理上限； 再 ×0.7 填充 ≈ 2000 万——这才是听起来「刚好两千万」的来源之一。 反推：L≈N/R；L≤1000→H=2；L≤100万→H=3。
记两套数： 树能力（一般行 ~500B）：H=3 大约还能挂到两三千万级（写满可更高）。 工程建议：单表常听到的~2000 万是体验/运维阈值——到了也未必炸树，但往往该考虑分库分表或归档。

行溢出：数据页 → 溢出页

叶子页 User Records 里发现大列需要外置
页内写入 20B 溢出页地址（Compact 还可能留前缀）
真正字节写入溢出页；不够再链下一张溢出页
读行时：先解析页内部分，再按指针拼出完整大列

undo：当前行 → undo 页版本链

UPDATE/DELETE 时，先把旧版本信息写进 undo 页
叶子行更新 trx_id，并把 roll_pointer 指到这条 undo
多次修改 → undo 记录互相串成版本链
回滚：沿链恢复；MVCC 读：沿链找对 Read View 可见的版本

读法：上半是物理包含与B+ 树分层；演进 / 分裂讲怎么长高、怎么拆页； 「树高估算」用 F、R 算不同 H 能扛多少行；下面两张卡是旁路—— 溢出页补大字段，undo 页补历史版本。
