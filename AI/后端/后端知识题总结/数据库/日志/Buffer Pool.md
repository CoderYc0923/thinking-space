Buffer Pool 是 InnoDB 的内存缓冲池，用来解决「数据在磁盘上，每次都读写盘太慢」的问题；按 16KB 页组织。

作用：用页级内存缓存加速读写并延迟脏页刷盘；持久性交给 redo + WAL。

原理（按流程）：

1. **启动**：申请一片连续内存，划成一个个 16KB 缓存页（起初多为空闲）。池里后续会缓存数据页、索引页、undo 页，以及 **Change Buffer**、自适应哈希等结构。

2. **读一条记录时**
   - 先看目标页是否已在 Buffer Pool：未命中则从磁盘把**整页**载入；命中则直接用内存页。
   - 若该页在 Change Buffer 里还有未合并的变更，载入/使用时会先把变更**merge**进页，再对外提供一致结果。
   - 页在内存后，二分扫 **B+ 树**找到对应叶子页，再在页内用页目录等找到行。
   - 若该位置被频繁**等值**访问，InnoDB 会在 Buffer Pool 上自动维护**自适应哈希索引（AHI）**：下次等值查找可先走内存哈希，近似 O(1) 落到缓冲池中的记录，少走几次 B+ 树；范围扫仍主要走 B+ 树。AHI 只在内存、不落盘，重启后按负载重建，可由 `innodb_adaptive_hash_index` 开关。

3. **写一条记录时**
   - **聚簇索引（数据页）**：所在页必须先在 Buffer Pool（没有就先从磁盘载入），不能省略读盘。
   - **undo**：更新/删除前在 Pool 里的 **undo 页**记下旧版本，并为此记 redo。
   - **改内存页 + redo**：修改 Buffer Pool 中的页，标成**脏页**，写 redo；脏页不立刻刷盘，后台择机刷回 `.ibd`。
   - **二级索引（Change Buffer）**：若是**非唯一二级索引**，且对应索引页**还不在** Buffer Pool：
     - 不必立刻为改二级索引去磁盘把那一页读进来（避免随机 IO）；
     - 把这次插入/删除标记等变更先记到 Pool 内的 **Change Buffer**；
     - 等以后该页因查询被读入，或后台 merge 线程工作时，再把缓冲的变更合并进真正的索引页。
     - 唯一二级索引、聚簇索引不适用这套「先缓冲再 merge」（唯一性等要立刻可见/校验）。
   - 提交仍按 redo/binlog 策略保证可恢复。

4. **串起来看**
   - 读：载页（可能先 merge Change Buffer）→ B+ 树定位（热点等值可走 AHI）。
   - 写：undo → 改聚簇页（必在 Pool）→ 二级索引页不在 Pool 时可进 Change Buffer → redo 保持久 → 后台刷脏 / merge。
   - Buffer Pool 负责「快」；redo 负责「安全」；Change Buffer 专门优化「二级索引页不在内存时的写」；AHI 专门优化「内存中的热点等值读」。
