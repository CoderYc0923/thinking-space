## 时间分区

时间分区一般两种场景：**数据库时间分区（MySQL）**、**业务前端按时间分段（如按天 / 小时统计）**



## 一、MySQL 时间分区（RANGE 按时间）

> 适用：按时间范围分区，日志、订单、账单表，按年 / 月 / 日拆分，提升大表查询、删除性能。
>
> 注意：分区字段**必须是主键 / 唯一索引的一部分**。

1. 新建表直接分区（按月份分区）

   ```sql
   CREATE TABLE `order_log` (
     `id` BIGINT NOT NULL,
     `create_time` DATETIME NOT NULL,
     `content` VARCHAR(255)
   ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
   PARTITION BY RANGE (TO_DAYS(create_time)) (
       PARTITION p202607 VALUES LESS THAN (TO_DAYS('2026-08-01')),
       PARTITION p202608 VALUES LESS THAN (TO_DAYS('2026-09-01')),
       PARTITION p202609 VALUES LESS THAN (TO_DAYS('2026-10-01'))
   );
   ```

   - `TO_DAYS()`：datetime 转天数，用于按天 / 月分区

   - 按小时用：`TO_SECONDS(create_time)`

2. 已有表改成分区表

   - ⚠️已有大量数据，先备份，InnoDB 分区不支持直接 alter 转换，建议新建分区表 + 迁移数据

3. 自动新增分区

   - MySQL 原生没有自动建分区，两种方案：
     - 定时脚本 /crontab：提前生成下一个月分区
     - 存储过程定时调用，新增 partition

4. 查询分区信息

   ```sql
   -- 查看表分区
   SELECT PARTITION_NAME,TABLE_ROWS FROM INFORMATION_SCHEMA.PARTITIONS 
   WHERE TABLE_NAME='order_log';
   
   -- 看SQL走了哪个分区
   EXPLAIN PARTITIONS SELECT * FROM order_log WHERE create_time >= '2026-08-01';
   ```

5. 删除旧分区（快速清理历史数据，比 delete 快很多）

   ```sql
   ALTER TABLE order_log DROP PARTITION p202607;
   ```

6. RANGE COLUMNS（推荐，直接用 datetime，不用函数）

   ```sql
   PARTITION BY RANGE COLUMNS(create_time) (
       PARTITION p202607 VALUES LESS THAN ('2026-08-01 00:00:00'),
       PARTITION p202608 VALUES LESS THAN ('2026-09-01 00:00:00')
   );
   ```

   - 优势：查询条件`where create_time > 'xxx'`可以直接分区裁剪，不需要函数包裹字段



## 二、业务层时间分区（后端 Java 举例：把数据切时间桶）

场景：统计，把数据划分成`0‑1点，1‑2点...`时间段。

```java
//按小时分区，时间戳分到对应小时桶
long bucket = timeStamp / (1000 * 60 * 60);
```



## 三、什么时候不要做时间分区

1. 表不大（几十万以内），直接索引即可，分区带来维护成本
2. 查询经常不带时间条件，无法触发分区裁剪，分区没有收益
3. 唯一索引不能带上分区字段，MySQL 不支持



## 四、常见坑

1. 分区字段不在 where 条件：扫描全部分区，性能变差
2. 唯一索引必须包含分区键，否则建分区报错
3. 忘记预创建新分区，新数据插入报错
