## 一、四种连接查询、笛卡尔积、内连接 INNER JOIN、左连接 LEFT JOIN

### 联表查询基础语法

1. 逗号隐式连接（不推荐，容易产生笛卡尔积）

   ```sql
   SELECT * FROM student,class WHERE student.class_id = class.class_id;
   ```

   

2. JOIN 显式连接（企业标准写法，可读性高）

   ```sql
   SELECT 查询字段
   FROM 表1
   [INNER/LEFT/RIGHT/FULL] JOIN 表2
   ON 两表关联条件; -- 核心：关联匹配规则
   ```

   

### 笛卡尔积（必避大坑）

1. 产生原因：多表查询**缺少 ON 关联条件**

2. 后果：表 1 行数 × 表 2 行数 全部匹配，海量无效数据，卡死数据库

   ```sql
   -- 错误！无ON条件，生成笛卡尔积，禁止使用
   SELECT * FROM student JOIN class;
   ```

   

### 四种连接详解

1. INNER JOIN 内连接（交集）

   - 含义：只返回**两张表能匹配上**的数据

   - 无匹配的数据直接过滤，不会出现 NULL

   - 日常统计、匹配查询最常用

   - ```sql
     -- 查询学生+对应班级名称，只保留有班级的学生
     SELECT
     	s.name,
     	c.class_name,
     	c.teacher
     FROM student s
     INNER JOIN class c
     ON s.class_id = c.class_id;
     ```

   - 

2. LEFT JOIN 左连接（左表全部 + 匹配右表）

   - 含义：**左表所有数据全部保留**；右表匹配不上时，字段填充 NULL

   - 业务场景：查询全部商品（左表）+ 对应订单，无订单商品也要展示

   - ```sql
     -- 查询全部学生，就算班级不存在也保留学生信息
     SELECT
     	s.name,
     	c.class_name
     FROM student s
     LEFT JOIN class c
     ON s.class_id = c.class_id;
     ```

   - 

3. RIGHT JOIN 右连接（极少使用，了解即可）

   - 含义：保留右表全部数据，左表无匹配填充 NULL

   - 替代方案：交换左右表，改用 LEFT JOIN，可读性更好

   - ```sql
     -- 保留所有班级，没有学生的班级也展示
     SELECT
         s.name 学生姓名,
         c.class_name 班级名称
     FROM student s
     RIGHT JOIN class c
     ON s.class_id = c.class_id;
     ```

   - 

4. FULL JOIN 全连接（MySQL 不支持）

   - 作用：左右表所有数据全部保留，无匹配填充 NULL
   - 替代方案：MySQL 使用 `LEFT JOIN UNION RIGHT JOIN` 实现
   
5. CROSS JOIN 笛卡尔积，第一个表的每一行和第二个表的每一行组合



## 二、多表连续 JOIN、多对多思想、联表 + 聚合综合实战

### 三表连续联查（业务最常用）

1. 需求：学生 + 班级 + 单科成绩 三张表关联查询

2. 执行逻辑：先联前两张表，再关联第三张表

   ```sql
   -- 查询每个学生、班级、各科分数
   SELECT
   	s.name,
   	c.class_name,
   	sc.subject,
   	sc.score
   FROM student s
   LEFT JOIN class c ON s.class_id = c.class_id
   LEFT JOIN score sc ON s.id = sc.student_id;
   ```

   

### 多对多关系设计（拓展，为复杂业务铺垫）

1. 一对多：A 一条对应多条 B；

2. 多对多：A 多条对应 B 多条，**必须建立中间关联表**

3. 示例：学生 <-> 课程（一个学生选多门课，一门课多个学生选）

4. 中间表：student_course (student_id,course_id)

   

### 联表查询 + GROUP BY 聚合统计（数据分析核心）

```sql
-- 统计每个班级的学生人数、班级平均分
SELECT
	c.class_name,
	COUNT(DISTINCT s.id)
	AVG(sc.score)
FROM class c
LEFT JOIN student s ON c.class_id = s.class_id
LEFT JOIN score sc ON s.id = sc.student_id
GROUP BY c.class_id,c.class_name;
```



### WHERE 过滤联表结果、联表分页

1. 联表条件过滤

   - ```sql
     -- 查询高一1班所有学生各科成绩
     SELECT
     	s.name,
     	sc.score
     FROM student s
     LEFT JOIN score sc ON s.id = sc.student_id
     WHERE s.class_id = 1;
     ```

   - 

2. 联表分页 LIMIT

   - ```sql
     -- 分页展示学生+班级，每页5条，第1页
     SELECT
     	s.name,
     	c.class_name
     FROM student s
     LEFT JOIN class c ON s.class_id = c.class_id
     LIMIT 0,5;
     ```

   - 

### INNER JOIN 和 LEFT JOIN 场景选择（面试必背）

1. INNER JOIN
   - 交集，只需要两边匹配成功的数据
   - 例如查询有成绩的学生、有订单的商品
2. LEFT JOIN
   - 需要完整保留左表全部数据，右表匹配不上时，字段填充 NULL
   - 全部商品（含无订单）、全部班级（含无学生）



### 题目

```sql
-- 输出班级名、学生姓名、科目、单科分数，只展示 1、2 班数据
SELECT
	c.class_name,
	s.name,
	sc.subject,
	sc.score
FROM class c
LEFT JOIN student s ON c.class_id = s.class_id
LEFT JOIN score sc ON s.id = sc.student_id
WHERE c.class_id IN(1,2);

-- 统计每个学生的姓名、班级、总分、平均分
SELECT
	s.name,
	c.class_name,
	SUM(sc.score),
	AVG(sc.score)
FROM student s
LEFT JOIN class c ON s.class_id = c.class_id
LEFT JOIN score sc ON s.id = sc.student_id
GROUP BY s.id,s.name,c.class_name;

-- 找出没有任何考试成绩的学生
SELECT
	s.name,
	c.class_name
FROM student s
LEFT JOIN class c ON s.class_id = c.class_id
LEFT JOIN score sc ON s.id = sc.student_id
WHERE sc.id IS NULL;
```





## 三、总结

1. 联表必须写 `ON` 关联条件，否则产生笛卡尔积，性能灾难
2. INNER JOIN：交集；LEFT JOIN：保留左表全部；RIGHT JOIN 极少使用
3. 多表联查连续使用 LEFT JOIN / INNER JOIN，关联条件依次书写
4. 联表可以搭配 WHERE、GROUP BY、ORDER BY、LIMIT 所有单表语法
5. 联表聚合统计时，GROUP BY 需要包含所有非聚合查询字段
6. 查询「左表全部数据，无匹配数据也要展示」统一使用 LEFT JOIN
