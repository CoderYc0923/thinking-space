## 一、基础定义

**DataWorks 是阿里云 PaaS 产品**，脱胎于阿里内部大数据平台，**一站式、全生命周期大数据开发 & 治理平台**。

简单理解：**大数据工作流开发、调度、数据治理、数据服务统一操作台**。

> 区分：
>
> - **DataWorks = 整套平台产品名称**
> - **DataStudio = DataWorks 内部【数据开发 IDE 模块】**（写 SQL、编排 DAG 工作流的编辑器）

## 二、底层对接引擎（计算引擎）

DataWorks 本身**不具备计算能力**，是调度与开发控制台，对接各类计算引擎：

1. **MaxCompute（主流离线数仓）**：T+1 离线批处理
2. **Flink**：实时流计算
3. **Hologres**：实时数仓、OLAP 交互式查询
4. **EMR（Hadoop/Spark）**：开源大数据集群
5. StarRocks、AnalyticDB、PAI 机器学习平台

## 三、九大核心模块

### 1. 数据集成（Data Integration）【数据同步】

大数据 ETL 第一步，数据源互通

- 支持 50 + 数据源：MySQL、Oracle、SQLServer、Kafka、OSS、MongoDB、Hive 等
- 任务类型：**离线全量 / 增量同步、实时同步、分库分表同步**
- 适用：业务库数据抽取到数仓

### 2. 数据开发（DataStudio）【核心开发】

数据开发人员日常使用最多模块

DataStudio开发界面

- Web 可视化 DAG 画布，拖拽编排任务依赖
- 节点类型：SQL 节点、Python、Shell、Flink、Notebook、数据对比节点
- 调度能力：分钟 / 小时 / 日周期调度、跨周期依赖、分支条件调度
- 流程：**开发→提交→代码评审→发布到生产环境**（严格隔离开发 / 生产）

### 3. 运维中心

任务上线后监控与运维

- 任务运行日志、报错告警、重跑、基线保障（保障报表按时产出）
- 全链路血缘诊断、失败影响分析

### 4. 智能数据建模

基于阿里数据中台方法论（分层建模：ODS/DWD/DWS/ADS）

- 可视化建表、维度管理、指标统一管理
- 规范数仓分层建设，统一指标口径

### 5. 数据地图（DataMap）

企业数据资产目录

- 表检索、**字段级数据血缘**（追踪数据从哪来、流向哪里）
- 表详情、产出责任人、访问热度

### 6. 数据质量（DataQuality）

数据监控，防止脏数据污染报表

- 表 / 字段级别规则：空值校验、波动监控、主键唯一性
- 规则失败触发告警、阻断下游任务

### 7. 数据服务（DataService Studio）

把数仓数据表封装成 HTTP API 对外提供查询

- 无需开发服务代码，可视化配置查询接口
- 权限控制、流量限流，业务系统直接调用数仓数据

### 8. 数据分析

自助取数、可视化探索，面向分析师（Quick BI 联动）

### 9. 数据安全与治理

敏感数据识别、权限管控、操作审计、数据脱敏

## 四、标准大数据工作流程（企业通用）

1. 使用【数据集成】同步业务数据库 → ODS 层
2. 在【DataStudio】编写 MaxCompute SQL，逐层加工 DWD→DWS→ADS
3. 设置调度周期，配置上下游依赖
4. 配置【数据质量】规则监控数据稳定性
5. 发布上线，【运维中心】监控每日运行
6. 通过【数据地图】梳理资产，【数据服务】对外提供接口

## 七、常见面试高频问题

1. **开发环境和生产环境隔离**：代码必须发布才能在生产执行，禁止直接操作生产
2. **基线**：核心任务设定最晚完成时间，超时自动告警，保障报表准时可用
3. **跨引擎调度**：同一个 DAG 工作流可混合 MaxCompute 离线任务 + Flink 实时任务
4. **调度依赖**：支持任务依赖，也支持**表依赖（等待上游表产出完成再执行）**
