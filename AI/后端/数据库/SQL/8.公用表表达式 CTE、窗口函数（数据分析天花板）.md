## 一、CTE 公用表表达式（WITH AS）

### 什么是 CTE

1. CTE（Common Table Expression）公用表表达式，使用 `WITH ... AS()` 定义**临时结果集**，仅当前 SQL 生效，等价轻量化派生表，可读性远优于多层嵌套子查询。

2. ```sql
   WITH cte名 AS (子查询)
   SELECT * FROM cte名;
   ```

3. 示例 1：基础 CTE（替代派生表）

   - 以往派生表写法（多层括号，可读性差）

   - ```sql
     SELECT t.name, t.total
     FROM (
     	SELECT s.name, SUM(sc.score) total
         FROM student s
         LEFT JOIN score sc ON s.id = sc.student_id
         GROUP BY s.id, s.name
     ) t
     WHERE t.total > 240;
     ```

   - CTE 优化写法

   - ```sql
     WITH student_total AS (
     	SELECT s.name, SUM(sc.score) total
         FROM student s
         LEFT JOIN score sc ON s.id = sc.student_id
         GROUP BY s.id, s.name
     )
     SELECT * FROM student_total WHERE total > 240;
     ```

   - 

4. 示例 2：多个 CTE 串联，逗号分隔

   - 多个临时表可以依次定义，后面 CTE 可以引用前面定义的 CTE

   - ```sql
     WITH class_avg AS (
     	-- 班级平均分
         SELECT class_id, AVG(score) avg_score FROM student GROUP BY class_id
     ),
     high_class AS (
     	-- 筛选平均分大于80的班级
         SELECT class_id FROM class_avg WHERE avg_score > 80
     )
     SELECT s.name, s.class_id
     FROM student s
     WHERE s.class_id IN (SELECT class_id FROM high_class);
     ```



### CTE两大优势

1. **可读性极强**：由上至下逐层定义，告别派生表层层嵌套

2. **同一条 SQL 内多次复用**，派生表只能使用一次

3. ```sql
   WITH base AS (SELECT * FROM student WHERE score >= 60)
   SELECT * FROM base WHERE class_id=1
   UNION ALL
   SELECT * FROM base WHERE class_id=2;
   ```



### 递归 CTE（Recursive CTE）⭐重点

1. 适用场景：树形结构、层级数据（部门树、分类树、生成连续数字 / 日期）

2. 语法模板：

   ```sql
   WITH RECURSIVE cte_name AS (
       -- 锚点成员：初始数据（起点）
       SELECT ...
       UNION ALL
       -- 递归成员：引用自身CTE，迭代查询
       SELECT ... FROM cte_name JOIN 业务表
   )
   SELECT * FROM cte_name;
   ```

3. 示例：生成 1~10 连续数字

   ```sql
   WITH RECURSIVE num AS (
       SELECT 1 AS n
       UNION ALL
       SELECT n+1 FROM num WHERE n < 10
   )
   SELECT n FROM num;
   ```

4. 业务场景示例：组织机构树形查询、日历日期维度表生成。



### CTE 注意事项

1. MySQL8.0 CTE 默认**不物化**，优化器会把 CTE 语句直接合并入主查询；部分场景下，多次引用 CTE 会重复执行子查询（和 PostgreSQL 行为不同）
2. CTE 只在当前单条 SQL 有效，执行完毕自动销毁
3. `WITH RECURSIVE` 必须加关键字`RECURSIVE`，即使不是递归也可以使用
4. 递归 CTE 一定要写终止条件，否则无限循环，数据库会报错



## 二、窗口函数 Window Function

### 窗口函数核心概念

1. 聚合函数 `GROUP BY`：分组后**一行一组**，合并数据，行数变少。

2. 窗口函数：**分组但不合并行**，原有行数保持不变，新增一列计算结果

3. 关键字：`OVER()` 窗口定义

   ```sql
   函数() OVER (PARTITION BY 分组字段 ORDER BY 排序字段)
   ```

   - `PARTITION BY`：窗口分区（等价 group by，窗口内分组）
   - `ORDER BY`：窗口内排序
   - 框架子句（ROWS/RANGE）：限定窗口计算范围

### 五大排序窗口函数（最常用）

1. ROW_NUMBER()

   - 连续编号，**不允许并列**；相同排序值依次 1,2,3,4

2. RANK()

   - 允许并列，并列会跳过序号：1,1,3,3,5

3. DENSE_RANK()

   - 允许并列，**不跳过序号**：1,1,2,2,3

4. ROW_NUMBER / RANK / DENSE_RANK 对比演示

   - ```sql
     SELECT
         name, score, class_id,
         ROW_NUMBER() OVER(PARTITION BY class_id ORDER BY score DESC) rn,
         RANK() OVER(PARTITION BY class_id ORDER BY score DESC) rk,
         DENSE_RANK() OVER(PARTITION BY class_id ORDER BY score DESC) dr
     FROM student;
     ```

   - PARTITION BY class_id：**按班级分区排名**，每个班级独立从 1 开始排名PARTITION BY class_id：**按班级分区排名**，每个班级独立从 1 开始排名

5. NTILE(n)

   - 将有序数据平均切分为 n 组，返回组编号

   - ```sql
     -- 每个班级学生划分成2个梯队
     SELECT
         name,score,class_id,
         NTILE(2) OVER(PARTITION BY class_id ORDER BY score DESC) tile
     FROM student;
     ```



### 偏移函数（行取值，报表神器）

1. `LAG(字段,偏移量,[默认值])`：取**上 N 行**数据

2. `LEAD(字段,偏移量,[默认值])`：取**下 N 行**数据

3. ```sql
   -- 示例：查看同班学生上一名分数
   SELECT
   	name, score,class_id,
   	LAG(score, 1) OVER(PARTITION BY class_id ORDER BY score DESC) prev_score,
   	LEAD(score, 1) OVER(PARTITION BY class_id ORDER BY score DESC) next_score,
   FROM student;
   ```



### 聚合窗口函数

1. 普通聚合函数配合 OVER ()，不再合并多行

2. SUM / AVG / MAX / MIN / COUNT

3. ```sql
   SELECT
       name, score, class_id,
       AVG(score) OVER(PARTITION BY class_id) class_avg, -- 班级平均分
       SUM(score) OVER(PARTITION BY class_id) class_total, -- 班级总分
       MAX(score) OVER(PARTITION BY class_id) class_max
   FROM student;
   ```



### 窗口框架（ROWS / RANGE，进阶难点）

1. 当 OVER 内写了 ORDER BY，默认框架：RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW，含义：分区第一行～当前行

2. 两种框架模式

   - ROWS：物理行，按行数限定

   - RANGE：逻辑范围，按数值区间（MySQL 支持有限）

   - ```sql
     -- 示例：累加求和（移动汇总）
     SELECT
     	name, score,
     	SUM(score) OVER(ORDER BY score DESC ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) accumulate
     FROM student
     ```

   - 常用范围关键词：

     - `UNBOUNDED PRECEDING` 分区第一行
     - `CURRENT ROW` 当前行
     - `N PRECEDING` 前 N 行
     - `N FOLLOWING` 后 N 行



### 经典业务场景

1. 分组内排名（班级成绩排名）
2. 环比、同比计算（LAG 获取上一期数据）
3. 移动平均、滚动求和
4. TopN 查询（配合 CTE + 窗口函数筛选 rn<=3）



### 窗口函数限制

1. 不能直接写在 WHERE 条件

2. 需要先 CTE / 子查询包裹再过滤

3. ```sql
   -- ❌错误
   SELECT * FROM student WHERE ROW_NUMBER() OVER(...) <= 3;
   
   -- ✅正确
   WITH r AS (SELECT *, ROW_NUMBER() OVER(...) rn FROM student )
   SELECT * FROM r WHERE rn <= 3;
   ```







## 三、核心背诵总结

1. CTE (WITH AS) 简化嵌套 SQL；RECURSIVE 递归 CTE 处理层级、序列
2. OVER () 窗口函数，分区 PARTITION BY、排序 ORDER BY
3. 排序三兄弟：ROW_NUMBER / RANK / DENSE_RANK
4. LAG/LEAD 获取相邻行数据，适合环比计算
5. 窗口函数结果过滤必须嵌套 CTE / 子查询

## 四、思考

1. CTE 和 派生表区别？CTE 可以多次复用吗？
   - CTE 使用 WITH 定义，可读性高，同 SQL 可多次引用
   - 派生表只能使用一次，嵌套复杂
   - MySQL8.0 CTE 默认不物化，多次引用可能重复执行
2. RANK 和 DENSE_RANK 核心区别，什么业务场景分别使用？
   - RANK 并列会跳号；DENSE_RANK 不跳号
   - 榜单评奖场景一般用 DENSE_RANK
3. 窗口函数为什么不能直接在 WHERE 中使用？
   - SQL 执行顺序：FROM -> WHERE -> SELECT
   - 窗口函数在 SELECT 阶段才计算，WHERE 执行时窗口结果尚未生成
4. PARTITION BY 省略后代表什么含义？
   - 省略 PARTITION BY，整个数据集作为一个大窗口，不再分区
