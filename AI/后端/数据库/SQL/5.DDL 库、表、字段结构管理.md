## 一、数据库管理 + MySQL 常用数据类型

### 数据库（schema）操作

1. 创建数据库

   - ```sql
     CREATE DATABASE school;
     -- 推荐写法：不存在才创建，避免报错
     CREATE DATABASE IF NOT EXISTS school DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
     ```

   - `utf8mb4`：真正完整 UTF-8，支持 emoji 表情（**优先使用，不要用旧 utf8**）

   - `COLLATE`：排序规则

2. 切换数据库

   - ```sql
     USE school;
     ```

3. 查看数据库列表

   - ```sql
     SHOW DATABASES;
     ```

4. 删除数据库

   - ```SQL
     -- 存在才删除
     DROP DATABASE IF EXISTS school;
     ```

### MySQL 主流数据类型（建表核心，选不对后患无穷）

1. 数值类型

   - | 类型           | 使用场景                     | 注意事项                                                     |
     | -------------- | ---------------------------- | ------------------------------------------------------------ |
     | `TINYINT`      | 状态字段：0/1、开关、性别    | -128~127；无符号 0~255                                       |
     | `INT`          | ID、普通数字，最常用         | ±21 亿；主键 id 首选。`INT(10)` 括号里数字**不代表存储长度**，只是显示宽度，不会限制存储数字大小！不要被这个迷惑 |
     | `BIGINT`       | 订单 id、大表主键、分布式 id | 超大整数，后端业务推荐                                       |
     | `DECIMAL(m,n)` | 金额、小数计算               | **禁止 float/double！存在精度丢失**m 总长度，n 小数位 `DECIMAL(10,2)` 金额 |
     | FLOAT          |                              | 二进制近似存储，小数运算丢失精度 ❌禁止存金额                 |
     | DOUBLE         |                              | 依然存在精度误差，仅科学计算场景使用                         |

2. 字符串类型

   - | 类型         | 使用场景                                                     | 注意事项                                                     |
     | ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
     | `VARCHAR(n)` | 短文本：姓名、地址、手机号，**可变长度**。varchar 设置合理长度，不要一律 varchar (255) | 可变长度，n 代表**最大字符数**;MySQL5.7/8.0，utf8mb4 下最大 n=21844 左右；只占用实际字符存储空间，节省空间 |
     | `CHAR(n)`    | 固定长度：验证码、uuid 编码                                  | 固定长度，n 范围：0 ~ 255；不足长度自动用空格补齐，查询时自动截断尾部空格 |
     | `TEXT`       | 大文本：文章内容、备注（不要滥用）                           | 65535 字符，大文本，不建议建立普通索引                       |
     | TINYTEXT     | 简短备注                                                     | 255 字符                                                     |
     | MEDIUMTEXT   | 长文本、富文本内容                                           | 16777215 字符                                                |
     | LONGTEXT     | 超大篇幅内容                                                 | 42 亿字符                                                    |

3. 时间日期类型

   - `DATE`：只有日期 2026-07-30
   - DATETIME：日期 + 时间 `2026-07-30 14:30:00`
   - TIMESTAMP：时间戳，受时区影响，上限 2038 年，新项目优先 DATETIME

4. JSON 类型

   - MySQL5.7+ 支持，现代业务常用

   - 专门存储 JSON 数组、JSON 对象

   - 优势：支持内置函数直接查询 json 内字段，不需要字符串截取

   - ```sql
     -- 示例：存储商品扩展属性、多标签、动态配置
     ext_info JSON COMMENT '扩展信息'
     
     -- 查询语法示例
     SELECT ext_info->>'$.height' FROM student;
     
     ```

5. 枚举与集合类型（了解即可，谨慎使用）

   - ENUM 枚举

     - 预先定义可选值，只能存入其中一个值

     - 缺点：新增选项需要 DDL 改表结构，分布式项目不推荐

     - ```sql
       gender ENUM('男','女','未知')
       ```

   - SET 集合

     - 可以同时存放多个预设值，用逗号分隔

     - 极少使用，业务一般用中间表或者 JSON 替代

     - ```sql
       tag SET('热门','新品','折扣')
       ```

     - 

6. NULL 说明

   - 字段允许为空代表可以存 NULL；尽可能业务上加 `NOT NULL`，减少空值带来的查询坑

7. 完整选型速查表（工作直接参考）

   - 用户 ID、主键：`BIGINT`
   - 状态 (0/1)：`TINYINT`
   - 金额、价格：`DECIMAL(10,2)`
   - 姓名、地址：`VARCHAR(50)`
   - 手机号：`CHAR(11)`
   - 文章正文：`TEXT`
   - 创建时间：`DATETIME`
   - 动态扩展属性：`JSON`
   - 生日：`DATE`

8. 高频易错点汇总

   - `VARCHAR(n)` n 是**字符数量**，不是字节；utf8mb4 一个汉字占 4 字节
   - 整数括号长度 `INT(11)` 只是展示宽度，无存储限制
   - TIMESTAMP 2038 上限，新项目一律 DATETIME
   - FLOAT/DOUBLE 禁止财务计算
   - CHAR 固定长度，频繁更新短字符串优先 VARCHAR
   - TEXT、BLOB 无法设置默认值，尽量避免 SELECT *
   - ENUM、SET 灵活性差，互联网业务尽量不用

## 二、建表、约束、ALTER 修改表结构、删除表

### CREATE TABLE 创建表（最重要）

```sql
CREATE TABLE IF NOT EXISTS student (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '主键id',
    name VARCHAR(20) NOT NULL COMMENT '学生姓名',
    age TINYINT COMMENT '年龄',
    gender VARCHAR(2) COMMENT '性别',
    class_id INT COMMENT '班级编号',
    score DECIMAL(5,1) COMMENT '考试分数',
    create_time DATETIME DEFAULT NOW() COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学生信息表';
```

参数说明：

- `ENGINE=InnoDB`：默认存储引擎，支持事务（必写）
- `COMMENT` 注释，团队协作必备

### 五大表约束（建表重点）

1. `PRIMARY KEY` 主键
   - 唯一、非空；一张表只能一个主键
2. `AUTO_INCREMENT` 自增，只能搭配整型主键
3. `NOT NULL` 非空约束，字段不能存 NULL
4. `DEFAULT` 默认值
5. `UNIQUE` 唯一约束：字段值不能重复（可以有一个 NULL）
6. 外键 `FOREIGN KEY`
   - 语法了解即可，**互联网业务极少使用**，容易锁表、耦合严重，业务层面代码控制关联

```sql
-- 示例：带唯一约束
CREATE TABLE IF NOT EXISTS user (
	id INT PRIMARY KEY AUTO_INCREMENT,
    phone VARCHAR(11) NOT NULL UNIQUE COMMENT '手机号唯一'
) ENGINE=InnoDB DEFAULT CHARACTER=utf8mb4;
```

### ALTER  TABLE 修改表结构（线上谨慎执行！大表改结构会锁表）

1. 修改表名称

   ```sql
   ALTER TABLE student RENAME TO student_infoo;
   ```

   

2. 添加新字段

   ```sql
   -- 在末尾添加字段
   ALTER TABLE student ADD COLUMN email VARCHAR(50);
   -- 指定位置添加（AFER 某字段 / FIRST）
   ALTER TABLE student ADD COLUMN height DECIMAL(4,1) AFTER age;
   ```

   

3. 修改字段类型 / 字段名称

   ```sql
   -- 修改字段类型、约束
   ALTER TABLE student MODIFY COLUMN age TINYINT NOT NULL;
   -- 修改字段名称+类型 CHANGE
   ALTER TABLE student CHANGE COLUMN height stature DECIMAL(4,1);
   ```

   

4.  删除字段

   ```SQL
   ALTER TABLE student DROP COLUMN email;
   ```

   

5. 添加 / 删除唯一约束、主键\

   ```sql
   -- 添加唯一索引
   ALTER TABLE student ADD UNIQUE uk_name(name);
   -- 删除唯一索引
   ALTER TABLE student DROP INDEX uk_name;
   ```

   

### 删除表 DROP TABLE

```sql
-- 安全写法，存在才删除
DROP TABLE IF EXISTS student;
```

### 思考

1. PRIMARY KEY 和 UNIQUE 的区别？
   - PRIMARY KEY：主键，非空 + 唯一，一张表只能一个；
   - UNIQUE：唯一约束，允许存在一个NULL，一张表可以多个；
2. NOT NULL 和 DEFAULT 默认值可以同时存在吗？
   - 可以共存，name VARCHAR(20) NOT NULL DEFAULT '未知'



### 总结

1. CREATE：创建库 / 表；ALTER：修改结构；DROP：删除库 / 表
2. 字符集统一使用 `utf8mb4`
3. 金额必须使用 DECIMAL，杜绝 float double
4. InnoDB 引擎支持事务，新项目默认引擎
5. ALTER 修改表结构，线上大表谨慎执行，容易造成锁表
6. DDL 语句直接改动结构，无法像 DML 一样简单回滚，操作前务必备份
