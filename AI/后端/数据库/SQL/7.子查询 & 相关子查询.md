## 说明

1. **主查询**：外层 SQL
2. **子查询**：`()`包裹的嵌套查询
3. **非相关子查询**：子查询可以独立执行，不依赖外层表
4. **相关子查询**：子查询引用外层主查询的字段，不能单独执行





## 一、非相关子查询三大类型（标量子查询、列子查询、派生表）

### 标量子查询（返回：1 行 1 列，单个值）

1. 使用场景：`=`、`>`、`<` 等比较运算符

2. 特点：子查询执行完毕返回一个数值

3. ```sql
   -- 查询分数等于全体最高分的学生
   SELECT id,name,score
   FROM student
   WHERE score = (SELECT MAX(score) FROM student);
   
   -- SELECT 子句中嵌入标量子查询
   SELECT
   	id,
       name,
       score,
       (SELECT AVG(score) FROM student) AS 全体平均分
   FROM student;
   ```

4. 风险：子查询返回多行时，使用`=`直接报错！此时改用`IN`



### 列子查询（返回：多行 1 列）

1. 子查询返回一列数据，搭配 `IN / ANY / ALL`

2. ```sql
   -- 查询存在不及格科目的学生id（子查询返回一批student_id）
   SELECT s.id,s.name
   FROM student s
   WHERE s.id IN (
       SELECT DISTINCT student_id FROM score WHERE score < 60
   );
   ```



### 表子查询【派生表】（多行多列，FROM 后使用）

1. 硬性规则：派生表**必须设置别名**

2. 适用场景：先聚合统计，再对外层过滤

3. ```sql
   -- 先统计每个学生总分，再筛选总分大于240的学生
   SELECT t.name, t.total
   FROM (
   	SELECT s.name, SUM(sc.score) AS total
       FROM student s
       LEFT JOIN score sc ON s.id = sc.student_id
       GROUP BY s.id, s.name
   ) t -- t 派生表别名，不能省略
   WHERE t.total > 240;
   ```



### 非相关子查询执行顺序

1. 优先执行内层子查询（只执行**一次**）
2. 将子查询结果传入外层主查询
3. 适合数据量不大场景





## 二、相关子查询、EXISTS、NOT EXISTS、ANY、ALL

### 相关子查询

1. 核心特征：**子查询引用外层主查询的表字段，无法独立运行**

2. 执行逻辑：外层每扫描一行，就执行一次子查询；外层 N 行，子查询执行 N 次

3. ```sql
   -- 查询存在考试成绩的学生
   SELECT s.id,s.name
   FROM student s
   WHERE EXISTS (
   	SELECT 1 FROM score sc WHERE sc.student_id = s.id
   );
   -- 子查询内 s.id 来自外层 student 表，典型相关子查询。
   ```



### EXISTS / NOT EXISTS（生产高频，重点！）

1. 判断**子查询是否存在满足条件的数据**

   - 找到第一条匹配数据立刻终止子查询（短路优化）
   - **只关心有无数据，不读取具体字段，统一推荐写 SELECT 1**

   - ```sql
     -- 有成绩的学生
     SELECT name FROM student s
     WHERE EXISTS (SELECT 1 FROM score sc WHERE sc.student_id = s.id);
     
     -- NOT EXISTS：没有任何考试成绩的学生
     SELECT name FROM student s
     WHERE NOT EXISTS (SELECT 1 FROM score sc WHERE sc.student_id = s.id);
     ```

2. IN VS EXISTS 核心对比（面试必考题）

   - IN(子查询)
     - 子查询先全部执行，把结果集合加载内存；
     - 子查询结果量大时性能差；子查询允许 NULL，容易出现诡异空结果
   - EXISTS
     - 相关子查询，短路匹配；**大数据量推荐 EXISTS**

3. 经验准则：

   - 子查询数据集小：IN、EXISTS 差距不大
   - 子查询数据集很大：优先 EXISTS
   - 关联字段无索引，两者都会变慢
   - 经典坑：IN 子查询返回包含 NULL，整个 IN 结果为空，查询不出任何数据，EXISTS 不受此影响



### ANY / ALL 运算符（了解，业务使用偏少）

1. 配合比较运算符 `> < = >= <=`

   - `ANY`：满足集合中**任意一条**即可

   - `ALL`：必须满足集合中**全部**

   - ```sql
     -- ANY：分数大于任意一个1班学生分数（大于最小值）
     SELECT name,score FROM student
     WHERE score > ANY(SELECT score FROM student WHERE class_id=1);
     
     -- ALL：分数大于所有1班学生分数（大于最大值）
     SELECT name,score FROM student
     WHERE score > ALL(SELECT score FROM student WHERE class_id=1);
     ```

   - 等价简写理解：

     - `> ANY` ≈  \> 最小值
     - `> ALL` ≈  \> 最大值



### 子查询常见限制与开发规范

1. MySQL 不支持`LIMIT`直接用于`IN`里面，可以包一层派生表

   ```sql
   -- 错误写法：WHERE id IN (SELECT id FROM student LIMIT 5)
   -- 正确写法，嵌套派生表
   WHERE id IN (SELECT t.id FROM (SELECT id FROM student LIMIT 5) t);
   ```

   

2. 不要嵌套过多子查询（三层以上可读性、性能下降，优先改用 JOIN）

3. 相关子查询本质循环遍历，外层大表注意添加索引，否则性能雪崩

4. 能 JOIN 实现的需求，复杂统计场景优先 JOIN，避免深层子查询





## 三、核心知识点汇总（背诵清单）

1. 子查询三类：标量子查询、列子查询、派生表（FROM 后必须别名）
2. 非相关子查询：独立执行；相关子查询依赖外层，循环执行
3. EXISTS 短路查找，大数据量优于 IN；NOT EXISTS 实现不存在匹配查询
4. ANY 任意满足，ALL 全部满足
5. 复杂子查询可以等价改写为 JOIN；深度嵌套子查询谨慎使用
