# 2026–2027 全栈 + Agent 跳槽规划

> 命主现状：传统业务公司全栈 · 正在学 Java 基础 · 数据库/部署未开始  
> 目标窗口：2027 年 3 月前具备跳槽条件  
> 主轴：前端基础 → Java 全栈 → CMS + AI → Agent 亮点 → 投递  
> 原则：深度 > 广度；8 个月只保「技术闭环 + 1 主作品 + 1 Agent + 跳槽材料」  
> 修订日期：2026-07-28

---

## 一、总目标（到 2027.3 要交得出的东西）

1. **技术闭环**：Java 基础 → Spring Boot → 数据库 → 简单部署 → 能独立做小全栈
2. **主作品**：1 个可演示的「CMS + 1 个 AI 能力」（公司版或个人脱敏版，至少一份可带走）
3. **亮点**：1 个能 5 分钟跑通的 Agent 流水线（建议绑小说创作或 CMS 场景）
4. **跳槽材料**：简历 + 项目讲解稿 + 10–15 家目标岗投递准备

## 三、流程节点清单

### P0 筑基（约 9 周：现在 → 9 月底）

#### 学习节点

- [ ] Java 基础收尾：OOP、集合、异常、IO、泛型、常用 API
- [ ] JDBC 概念 + **MySQL 基础**（库表、CRUD、索引直觉、简单联表）
- [ ] Maven/Gradle 二选一（建议 Maven）
- [ ] Git 日常流（branch / PR 心态 / 别只会 commit）
- [ ] HTTP / JSON / REST 直觉
- [ ] **Spring Boot 入门**：一个模块里完成「用户/文章」级 CRUD API
- [ ] 前端：用已会的技术调自己的 API（不必学新框架）

#### 产出节点

- [ ] 本地跑通：`文章 CRUD` 小项目（表 + API + 简单页或 Apifox 可测）
- [ ] 笔记：常见报错与解决（面试会问「你怎么排查的」）

#### 此阶段先不做

- K8s、微服务、复杂中间件
- 多 Agent 框架大而全
- CMS 大页面开工（最多画表结构草稿）

---

### P1 CMS MVP（10–11 月）

#### 产品范围（锁死）

- [ ] 登录 / 角色（至少 admin + editor）
- [ ] 栏目 + 文章 CRUD、草稿/发布
- [ ] 列表分页、基础校验
- [ ] 管理端页面（现有前端栈即可）
- [ ] README：如何本地启动

#### 工程节点

- [ ] 表结构设计（用户、角色、栏目、文章）
- [ ] 分层：Controller / Service / Mapper（或等价）
- [ ] 统一返回体、基础异常处理
- [ ] 环境配置：`dev` 本地可跑

#### 双轨策略

- [ ] 若公司允做：公司 CMS 按同一 MVP，**书面确认范围与简历可写**
- [ ] 个人仓同步脱敏版（换业务名），保证可带走

#### 10/31 检查

浏览器能走完「登录 → 写文章 → 发布 → 列表可见」。  
否则砍权限/栏目，先保文章流。

---

### P2 AI + Agent（12 月 – 2027.1）

#### CMS 只做一个 AI 能力（三选一，选一做透）

- [ ] 文章摘要 / 标签生成，或
- [ ] 发布前检查（错别字、敏感词、结构），或
- [ ] 站内 RAG 问答（基于已发布文章）

#### Agent 节点（建议绑小说，故事更好讲）

- [ ] 明确输入输出：如「题材 → 大纲 → 一章草稿 → 一致性检查」
- [ ] 工具调用 ≥ 2（写文件 / 查设定集 / 调用模型等）
- [ ] 失败重试或人工确认一步（显出「生产味」）
- [ ] 5 分钟演示脚本写好

#### 部署（够用即可）

- [ ] 会把后端打成 jar / Docker 其一
- [ ] 云主机或 Serverless 能公网演示，或本地 + 录屏兜底
- [ ] 配置与密钥不进仓库

---

### P3 跳槽收口（2027.1 – 3 月）

- [ ] 简历：公司业务一笔带过 + CMS/AI/Agent 用结果说话
- [ ] 项目讲解 3 分钟版 + 10 分钟版
- [ ] 面试题库：Java 基础、MySQL、Spring、事务、索引、HTTP、项目坑
- [ ] 目标公司清单 15+（AI 应用 / SaaS / 要全栈且上 AI 的团队优先）
- [ ] 1 月起投递；2–3 月集中面试
- [ ] offer 对比：是否继续让你做 Agent/全栈，而不只是切图或纯 CRUD

## 五、注意事项

### 1. 进度依赖（不可跳步）

```
Java 基础 → SQL → Spring CRUD → CMS → AI → Agent → 投递
```

数据库没学就不要开 CMS 大需求。

### 2. 公司项目陷阱

- 无范围确认不上大模块
- 需求膨胀时用「MVP 清单」挡
- 代码归属不清时，个人仓脱敏版必须有
- 公司项目当**背书**，个人仓库当**证据**

### 3. 技术选型克制（按当前进度）

| 层 | 建议 |
|---|---|
| 后端 | Java 17+、Spring Boot 3、MyBatis 或 Spring Data JDBC/JPA 选一个学透 |
| 库 | MySQL |
| 部署 | 先 jar + 一台云主机，或 Docker 单容器 |
| Agent | 先官方 SDK / 简单编排，别一上来上重型多 Agent 平台 |
| 前端 | 沿用现有栈，P0–P1 不学新框架 |

### 4. 简历叙事

「传统公司全栈」不是减分，话术建议：

> 在真实业务约束下，独立（或主导）落地 CMS，并接入可演示的 AI/Agent 能力。

### 5. 跳槽节奏

- 2026 下半年以作品为主
- **不要为了「赶三月」在材料未齐时裸辞**
- 三月是目标窗，不是死线迷信；未齐可顺延春招尾声

### 6. 验收口径（防自我感觉良好）

| 阶段 | 验收标准 |
|---|---|
| P0 | 别人按 README 能调通你的 API |
| P1 | 你能直播点点鼠标走完发文 |
| P2 | Agent 现场跑完一条任务，能解释失败怎么处理 |
| P3 | 能不看稿讲清架构取舍与踩过的坑 |

### 7. 命盘节奏备忘（文化参考，非决策指令）

- 2026 换运年：宜定赛道、攒作品，忌冲动裸辞乱跳
- 技能产品化、外出/迁移求职与主轴同向
- 注意过劳：消化、睡眠、可持续输出

## 七、行业与岗位方向（简表）

| 优先级 | 方向 |
|---|---|
| 最贴 | AI 应用 / Agent 相关软件（内容、创作、效率类） |
| 次贴 | 传统业务全栈，但团队在上 AI（你负责接入与产品化） |

岗位关键词示例：全栈、AI 应用开发、LLM 应用工程、Agent 开发。
