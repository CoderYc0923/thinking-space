# 家用/宠物AI机器人 · 技术选型定稿（自学版）

> 读者定位：前端 + Java 基础，硬件/嵌入式从零学起。本文是**自己看的定稿备忘**，按「原则 → 架构 → 原型 → 产品双路线 → 落地」组织；原型与量产刻意分开写，避免混成一锅。

---

## 0. 一句话定位

**本地 AI 大脑 + 家用自主移动 + 宠物陪伴交互**；全程无需公网流量、无需物联网卡、无需云端算力。

开题句（可直接用）：本项目采用离线本地化 AI 架构，基于 ROS2 与 MQTT 内网通信，以本地 LLM/视觉/语音构建 AI 大脑，实现对话、宠物识别、离线语音与自主导航陪伴；高低指令分层——底层运动永远本地，LLM 只出高层任务。

---

## 1. 核心原则（决定所有选型）

1. 不依赖公网、不依赖云端、不需要物联网流量卡
2. AI 大脑完全在局域网离线运行；断网（拔掉宽带）仍完整可用
3. 机器人本体只负责运动、感知、安全；高层对话 / 任务理解 / 宠物识别 / 陪伴逻辑由「大脑」承担
4. 隐私第一：语音、画面、对话上下文不上传任何外网服务器
5. 分层安全：LLM 只输出高层任务指令，**不直接控制电机转速**；急停与避障永远本地
6. 低成本、软件驱动、可独立开发；硬件性能不够则**降级**，不做云端兜底

### 明确排除

| 排除项 | 原因 |
| ---- | ---- |
| 云端 API 当大脑 | 数据上传，违反隐私 |
| PC 作为 AI 大脑**交付终端用户** | 普通用户不会长期开 PC，不具备产品化 |
| 消费级本体直接跑 7B/14B | 成本、功耗、内存不合适 |

> 注意：PC + 大模型**只用于自己 Demo/学习验证**，不等于量产交付形态。

## 2. 架构原理（先搞懂再选型）

### 2.1 行业常见 vs 本项目

| | 头部机器人常见 | 本项目（目标形态） |
| ---- | ---- | ---- |
| 小脑（本体） | 实时控制、避障、导航、传感器、安全停机（必须本地） | 同左 |
| 大脑 | 多为云端大模型 | **本地**大脑（PC 原型 / 手机 / 板端） |

本方案 = **本地小脑 + 本地 AI 大脑**（可先跑在家里电脑，后期端侧 NPU / 手机）。

### 2.2 WiFi 与流量（最易混淆，必须钉死）

- 机器人 WiFi = **局域网无线网线**，连家里路由器，只做内网通信
- **不需要** 4G/5G 模块、物联网卡、任何流量套餐
- 仅当主动要外网远程操控 / OTA / 云端记忆时，才用家庭宽带（可选，非主力）
- 固件默认：关闭外网访问、日志上传

### 2.3 两种工作模式

| 模式 | 说明 | 能力 |
| ---- | ---- | ---- |
| 纯内网离线（主力） | 无公网、无流量、无云端 | 导航、避障、宠物识别、语音对话、AI 任务、全屋巡检、陪伴 |
| 联网增强（可选） | 仍用普通家庭 WiFi，不要物联卡 | 外网远程访问、云端记忆、OTA |

### 2.4 通用四层架构（原型与产品共用）

1. **设备感知层（小脑）**：实时运动、传感器、SLAM、避障、紧急停机、轻量视觉；**永远本地**
2. **内网通信层**：MQTT 消息总线（传感器/图片快照/高层任务）；账号密码鉴权
3. **AI 大脑层**：LLM + ASR + TTS +（原型可含 Agent 编排）；部署位置随阶段变化
4. **交互层**：Vue 控制台（原型）/ 手机 App（产品，可选）

完整链路（概念）：`机器人硬件 ⇔ MQTT ⇔ AI 服务/App ⇔ 前端控制台`

优势：解耦、低延迟、内网闭环、完全离线可用。

## 3. 阶段划分（你怎么从零走到产品）

| 阶段 | 大脑在哪 | 目的 |
| ---- | ---- | ---- |
| **A. Demo 原型** | 家里 PC（Ollama） | 零硬件也能先学通交互、导航逻辑、Agent；你当前最该先做 |
| **B. 平价量产 · 路线 D** | 用户手机 App 本地推理 | 硬件成本最低，隐私与成本平衡，**推荐首选产品线** |
| **C. 高端独立 · 路线 C** | 机器人 RK3588S 板载 | App 可关，整机独立对话/巡检/陪伴 |

对你个人路径建议：**先 A（软件+仿真）→ 再买入门小车练 ROS2 → 再评估 D/C 样机**。Java 可留给日后管理后台；机器人 AI 业务侧以 Python 生态为主（见下）。

## 4. 阶段 A：Demo 原型技术栈（学习/验证用）

### 4.1 语言与框架

| 项 | 选型 | 说明 |
| ---- | ---- | ---- |
| AI/机器人业务 | **Python** | ROS2 原生、LLM/YOLO/语音/Agent 生态最全；行业原型主流 |
| 管理后台（可选、后期） | Java | 适合后台管理，**不适合**当 AI+机器人实时业务主后端 |
| 机器人框架 | **ROS2 Humble** | SLAM、自主导航、避障、传感器、运动调度 |
| 通信 | **MQTT 局域网** | 核心总线 |
| 前端 | **Vue3 + Three.js** | 复用你最强技能：状态面板、实时画面、地图、3D、指令、语音入口 |
| 存储 | 原型 SQLite + Redis；产品化可 PostgreSQL | |
| 仿真 | **Gazebo** 家庭场景 | 0 成本先跑通 AI+导航，再上实体 |

### 4.2 原型期 AI（可更大、更爽，只跑在你 PC 上）

- **LLM**：Ollama（Qwen-7B/14B）— 陪伴对话、指令理解、任务拆解、Agent
- **视觉**：YOLOv8/v11 — 人、宠物、障碍物、家用物品、跟随
- **语音**：Whisper（ASR）+ Piper（TTS）— 全程无网

### 4.3 原型硬件（入门、低成本）

- 主控：带 WiFi 的开源机器人小车（支持 Micro-ROS / ROS2）
- 传感器：摄像头 + 激光雷达（可选）
- 通信：内置 WiFi 连家庭路由器
- 不需要物联卡 / 4G/5G / 公网

### 4.4 原型开发顺序建议

1. Gazebo 仿真跑通导航 + MQTT + 假 AI 指令
2. PC 上 Ollama + Whisper/Piper + YOLO 打通「说 → 想 → 下发任务」
3. Vue 控制台串起来
4. 再接实体小车

## 5. 产品化：共用模型基线（比原型更小）

量产侧用轻量模型，适配手机 / 板端 NPU：

- **LLM**：Qwen1.5B / Qwen2.5-2B，4bit 量化 — 对话、语义、Agent 多步拆解
- **视觉**：YOLOv8n — 人、猫、障碍物（本体可先跑轻量视觉）
- **语音**：Whisper 量化版（ASR）+ Piper（TTS）

重要约束：选定纯离线，**不做云端兜底**；硬件不达标 → 禁用 LLM 对话，仅保留底盘基础能力。

## 6. 路线 D：平价量产｜LLM 在手机 App（推荐首选）

### 架构

`机器人底盘（RK3566） <--> 局域网 MQTT <--> 用户手机 App（全部 AI 大脑）`

### 硬件与成本

1. 主控：RK3566 SOM  
   - 批量千片约 150~250 元；零售开发板约 300 元  
   - NPU ~0.8TOPS：跑 YOLOv8n、传感器、Micro-ROS、MQTT，**不跑大模型**
2. 外设：底盘电机、电池、摄像头、可选激光雷达、WiFi、音箱
3. 手机：用户自备；App 本地 NPU 跑 LLM、ASR、TTS

### 数据流

1. 摄像头画面 → 本体 YOLO 识别；传感器/地图状态经 MQTT → 手机
2. 手机麦 → App 内 Whisper ASR
3. App 内 LLM 理解 + Agent 规划 → 高层任务（如：`前往客厅寻找猫咪，拍摄照片`）
4. MQTT 下发任务 → 机器人本地规划路径、避障、执行 → 图片回传 App
5. Piper TTS 在手机合成 → 手机或机器人音箱播放
6. 音频/图片/对话上下文**仅存手机本地**，不发外网

### 优点

- 机器人硬件成本最低，适合走量
- 完全离线闭环，数据不出家庭局域网
- 复用手机 NPU，本体不必上昂贵大算力板
- 高低指令分离，手机不直接控电机

### 短板（必须接受的产品现实）

- App 需前台/前台服务；安卓易杀后台；iOS 后台推理限制严
- 低端机（内存＜8G、老 SoC）跑不动本地 LLM → 仅基础移动/避障/跟随
- App 关闭后：对话消失，底盘基础能力仍可运行

### 隐私要点

- MQTT 仅局域网；固件禁外网
- LLM/ASR/TTS 模型内置 App，无需联网下权重
- 音视频/对话默认内存临时缓存；持久化需用户手动开；无自动上传
- MQTT 用户名+密码，防内网窃听

### 降级逻辑

| 状态 | 行为 |
| ---- | ---- |
| 手机达标 + App 前台 | 全套 AI（对话、看图、任务、陪伴） |
| App 退后台 / 被杀 | 关 LLM 对话；保留 SLAM、避障、跟随、拍照 |
| 手机跑不动 LLM | 禁用 AI 对话；仅底盘基础功能 |

## 7. 路线 C：高端独立｜LLM 在机器人 RK3588S

### 架构

`机器人整机（RK3588S）内置全套 AI`；手机 App **可选**控制面板——App 关着也能语音对话、巡检、宠物互动。

### 硬件与成本

1. 主控：RK3588S SOM  
   - 批量千片约 450~600 元；零售开发板约 700~1200 元  
   - NPU ~6TOPS：板载 YOLO、Whisper、Qwen1.5B/2B 量化、Piper
2. 外设：底盘、大容量电池、**散热**、摄像头、可选雷达、WiFi、板载扬声器  
   → 整机物料成本显著高于 RK3566，必须做散热设计

### 数据流

1. 摄像头 → 本地 YOLO  
2. 板载麦 → Whisper ASR  
3. 板载 LLM → 对话 / Agent → 高层任务  
4. 本地底盘执行导航避障  
5. Piper → 板载音箱  
6. 图/声/对话存机器人本地，**不经手机、不访外网**

### 优点

- 完全独立，不需手机 App 常开
- 感知+推理全在本体，隐私等级最高
- App 只做状态查看，退出不影响 AI

### 短板

- 主控与整机成本高，定位高端
- NPU 持续推理功耗高、发热、续航变差
- 开发量大：RKNN 转换、算子适配、板载调试难于 RK3566

### 隐私要点

- 固件默认禁外网；模型预装本地
- 本地存储，无自动外发
- MQTT 内网鉴权

### 降级逻辑

| 状态 | 行为 |
| ---- | ---- |
| 开机正常 | 全套本地 AI |
| NPU 过热保护 | 关 LLM；底盘继续；可保留预设简单语音指令 |

## 8. 路线 D vs C 总表

| 对比项 | D 手机 App 扛 LLM（平价） | C RK3588S 板载 LLM（高端） |
| ---- | ---- | ---- |
| AI 大脑位置 | 手机 App 本地 | 机器人板载本地 |
| 主控 | RK3566，批量 150~250 元 | RK3588S，批量 450~600 元 |
| 依赖手机 App | 需要；关则对话失效 | 不需要；App 可选 |
| 隐私 | 内网闭环，数据在手机 | 数据全在本体，不经手机 |
| LLM | Qwen1.5B/2B 4bit，手机 NPU | 同模型，板端 NPU |
| 硬件成本 | 低，大众消费 | 高，高端 |
| 核心痛点 | 后台管控、低端机跑不动 | 成本、发热、续航、RKNN |
| 断网可用 | 要手机与机器人同局域网 | 完全独立，可不需要手机 |

## 9. 阶段落地建议（决策顺序）

1. **Demo**：PC 局域网 + Ollama Qwen7B（或 14B）快速验证交互、导航、Agent；暂不顾量产算力  
2. **平价样机**：优先 **路线 D**  
3. **高端样机**：再做 **路线 C**，面向愿为「独立离线」买单的用户

## 10. 行业趋势（与本方向对齐，备忘）

1. AI 从云端下沉到本地 / 端侧  
2. 断网可用成为家用机器人标配  
3. 高低指令永久分层：AI 不管底层电机  
4. 局域网直连替代公网依赖 → 更隐私、更低延迟  
5. 竞争转向 Agent 任务理解，而非堆硬件（你的切入点：软件 + AI）
